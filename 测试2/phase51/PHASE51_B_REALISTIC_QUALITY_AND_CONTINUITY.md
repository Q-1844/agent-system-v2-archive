# B｜写实成片质量与镜头衔接修复

前置：A 已使正式生产与恢复入口可用。阅读 [总控](PHASE51_00_EXECUTION_GUIDE.md) 与 [A 批](PHASE51_A_RUNTIME_EFFICIENCY.md)。本批继续使用克苏鲁追船，先修已出现的问题，不另找新故事或新模型。

## B1. 用可观看的失败清单确定修什么

定位最近克苏鲁项目的原始视频、实际选用版本、时间线和源素材。先看完整候选，再看相邻镜头和具体问题。保留用户对写实质感与尾帧接续的正面反馈，也保留与 Grok 差距明显的判断；不能仅依赖报告里的“通过”标签。

每个问题记录镜头、候选版本、源视频时间点、成片时间点、截图或片段、用户原话、类型及严重度。优先选影响最大的两至三类问题作定点修复；有证据的系统接线缺陷可以同时修，不把所有小瑕疵扩成一套新架构。

| 优先级 | 例子 | 处理要求 |
|---|---|---|
| 关键失败 | 船长与大副串位／分身；第三名船员凭空出现；人物或船变形；动作结果无因；追击关系消失 | 拒绝进入保留区间，查根帧、输入、决策或模型结果 |
| 明显失败 | 动作或方向接不上；位置突变；怪物尺度无理由变化；冻结／黑帧；接缝声音突断 | 修具体镜头、边界或装配问题，复核受影响下游 |
| 轻微问题 | 保留区间外的短暂抖动，非关键背景局部不稳 | 可裁掉或保留为候选已知问题；不得宣布无瑕疵 |
| 模型难以完成 | 合法输入、合理动作拆分后仍反复产生同类错误 | 换当前可用的镜头实现，保留同一叙事信息；报告能力边界 |

不用“视频生成成功”“首帧漂亮”或总体相似度代替以上判断。最终目标是保留片段内看不到明显失败，不能保证生成源素材每一帧都完美。

## B2. 先核验 Skill 是否真的进入执行链

逐项对应：用户曾提供的候选包、当前权威 Skill、注册和绑定版本、Agent 实际加载内容、工具决策、编译后请求、真实产物。无法取得原始候选包时明确写缺失，不把执行侧重建包自动等同于用户原包。

检查是否有“规则写了但没加载”“Skill 绑定只作用于一条路径”“重试时参数或参考丢失”“复杂计划原样倾倒进生成 prompt”“换模式后还沿用旧模式规则”等问题。确认责任层后修正，不先把全部失败归因于 Skill 不够专业。

规划保持结构化，发给模型的提示词要围绕这个镜头的可见动作、动作结果和必要运镜；图片已经承担的身份、构图与风格信息不反复堆砌。精简前后需比较关键约束是否仍在，不能删除人物、动作因果或场景状态。

模型输入字段、模式互斥和参考上限由当前适配器校验；叙事与方法选择归 Skill；镜头 ID、角色 Look、位置和具体实验属于项目事实或试验记录。复用现有文件组织，只修被证据证明有问题的条款。

## B3. 为追船场景建立足够的连续性依据

从已批准素材与原剧情提取，而非重新设计角色。只补当前镜头确实缺少的依据：

| 对象 | 必须稳定的内容 |
|---|---|
| 船长 | 身份、外观与服装；当前站位；负责的动作；衣物湿润或受损状态 |
| 大副 | 与船长清楚区分的身份与外观；当前站位；操作或观察对象 |
| 船 | 同一船体、船舱与驾驶位置；船头船尾；关键道具与障碍 |
| 怪物 | 同一实体的关键外观和相对尺度；当前距离、方位及威胁方式 |
| 海面与天气 | 同一空间、光照、风浪及剧情状态，变化有原因 |

角色 Look 负责身份；场景图负责空间。用于空船或环境的参考应排除无意入画的人，避免第三人污染后续镜头。双人镜头明确“谁在何处做什么”，逐镜选择最少但足够的合格参考，不机械塞入整包角色、服装、场景和怪物参考。

角色处在远景、背面、遮挡或极端光照时，检查身份信息是否足够；需要近景时可重新建立合格根帧。修新根帧仍须维持当前空间和剧情状态，不能突然让衣服变干、道具换手或人物换位置。

建议利用现有镜头计划增加一份短拍摄记录：叙事作用；主要动作与结果；起止状态；两人及怪物／船的位置；运动轴线；必要参考及版本；生成方式；预计可剪区间；关键动作不可删。它是现有计划的补充，不强制新增数据库表。

## B4. 保留尾帧接续，按边界选择方法

| 边界情况 | 候选处理 | 要检查的重点 |
|---|---|---|
| 同一空间、同一动作继续，前镜端点合格 | 真实保留端点作为下一镜起步的合法路径 | 下一镜真实开头是否承接；身份与动作是否继续 |
| 前镜空间可用，但远景／背面身份信息不足 | 当前模型可用的再锚定或重建首帧路径 | 补回身份同时不破坏动作和空间；承认是新画面 |
| 换机位、换景别或新的叙事过程 | 正常切镜；按计划重新建立首帧或用合法参考模式 | 轴线、视线、位置和事件是否可理解 |
| 上游人物／动作／船已错 | 修上游，或用有叙事依据的新镜头重新建立 | 不让错误端点成为新的身份或动作依据 |
| 两个拟保留端点都合格，连接确实断裂 | 先查裁切与切点；必要时再测试桥接 | 不为所有切镜增加过渡，不用桥接掩盖错片 |

具体模型能力以当前出站请求为准。参考模式可以重新构图，不能记作严格首帧接续；用 Look 与旧帧生成的新图是重建首帧，不能记作原始真实尾帧；首尾帧模式也仍需核对真实生成结果。当前不支持的输入组合不得由 prompt 假装实现。

### 接力依据必须对应最终保留片段

源素材至少 8 秒、默认 10 秒；成片可以保留其中完整有效的动作段。抽取接力端点时记录源视频版本、裁切范围、实际显示帧／时间戳、帧文件与内容依据。变速、转场或其他处理存在时，确认下一镜依据的是观众实际看到的状态。

不能直接把 out 时间点当作最后显示帧，也不能固定假设所有视频帧率相同。裁切、选版或关键处理改变后，重新检查端点与下游 freshness。若下游仍然接得上，可保留并记录复核；否则修受影响镜头，不机械重做全片。

上传或重托管帧时核对图片内容。通过图像生成再次“托管”而改变像素的图不能继续冒称真实抽帧。URL 可访问、图片语义正确、版本对应均需满足。

## B5. 动作、剪辑和音效的验收

### 动作与空间

先看观众能否理解追击：船向哪走、怪物从哪来、两人看什么、做了什么、为何产生下一个结果。屏幕方向允许因有依据的换机位改变，不能把任意方向变化都当错误；要检查世界方位和可读性。

过载镜头优先减少相互冲突的动作或拆成合理镜头。一个镜头应有清楚的主要动作与结果，必要的连续子动作可以保留；不把单动作规则写成所有影片的硬上限。拆分必须保留原来的危险、选择和结果，不能为提速把追逐改成海面风景。

两人接触道具、转向、操作、回头或躲避等关键时刻提高检查密度。看完整过程，防止手／道具脱离、人物瞬移、位置交换、目标动作未完成却突然跳到结果。

### 裁切和装配

能裁掉的是不影响叙事与下一镜的头尾错误。交接、接触、躲避、操作和关键因果出错时，不能删掉过程再宣布完成。裁切记录需说明保留了什么动作、删掉了什么问题、是否改变接力依据。

先检查无特效的真实切点。身份或空间断裂不能靠淡化、闪白或很长叠化蒙混；正常切镜无需像素级一致。装配复核帧率、比例、时间戳、重复片段、缺镜、黑帧和意外冻结。需要转码时按统一输出规格处理，不把模型源画质下降当系统提速。

### 音效

保留合格的海浪、引擎、风声、撞击等原生声音。检查环境声在切点突变、音量跳跃、重复撞击、无因音效、失真和视频错位。可用正常的音量调整与音频过渡改善环境连续性；关键动作音效仍须对应动作。无必要时不添加旁白、TTS 或新 BGM。

发现不需要的对白、背景音乐或无因声音时列出具体区间和处理方式，不直接把整片静音标成“音效保留”。

### 审查能力与效率

沿现有 Visual Review 检查首帧、过程、关键动作、保留末帧和每个接缝；普通区间合理采样，疑点加密。技术检查可自动化，审查结果绑定视频和裁切版本。抽帧、审查和下载尽量复用；输入、版本或检查标准改变则重新检查相关部分。

完整视频理解或人工播放与抽帧筛查分开记。工具只能检查抽帧时，不能称已逐帧审查全部视频；提供完整可播放候选，标明覆盖和疑点。最终视觉接受仍由用户决定。

## B6. 定点修复与 Skill 沉淀

选择既有失败中最有价值的两至三类：例如人数污染、双人动作、直接接力或换机位接缝。一次实验只改变主要怀疑因素；保留同一剧情、资产、源时长和其他配置。模型随机性存在时，不以一条好结果证明规则稳定。

| 用例 | 最小要验证的内容 |
|---|---|
| B-T01 空船场景／双人输入污染 | 真正参考和最终保留片段均无意外第三人 |
| B-T02 双人关键动作 | 身份、站位、操作对象和动作结果保持一致 |
| B-T03 合格端点直接接续 | 真实开头承接，持续段身份与动作合格 |
| B-T04 换机位或正常切镜 | Agent 不强迫接旧尾帧；空间与因果仍可理解 |
| B-T05 裁切变化后恢复 | 下游引用正确端点或经复核保留，不默用旧尾帧 |
| B-T06 全片音画接缝 | 保留原生音效，技术流和动作声音无明显断裂 |

同一策略连续两次出现同类失败，应分析输入、绑定、动作负荷与模型路径，改变有根据的策略再试。没有新假设就停止机械重复；这是防止空转，不是“免费也只能生成两条”的额度限制。保留首次结果、全部有价值候选和失败原因。

确定为规则问题才改正式 Skill。每条修订应包括触发条件、动作、禁用条件、失败后处理和证据位置，删除冲突或重复条款。接线缺陷在代码层修，单个坏候选先修候选，不能为一次成功加入强制新流程。

B 放行需有：核心失败的可观看前后对照；Skill 加载及真实请求证据；真实端点与裁切依赖可用；导演与装配能通过正式入口交出完整候选。无法解决的模型问题明确列为 C 的质量风险，不能用“流程跑通”掩盖。

版本：1.0　日期：2026-10-09　执行对象：可读取真实项目的 Claude Code／Zcode

## 1. 本轮的决定

先优化生产系统，再改进成片，再用同一个“克苏鲁追船”任务复测。保留现有六个 Agent、正式 Skill 和 canonical／ownership／OCC／receipt／资源锁底座。优先解决流程推进、有效成果复用和局部恢复，暂不扩大并发，不建设新的工作流框架。

用户对写实质感的反馈已经支持继续投入。本轮的产品目标是：在现有模型能力内，更快交出人物稳定、动作可读、接缝顺畅的完整候选。Grok 是用户的质量参照；“低配版”的定位不表示本轮已经证明两者效果接近。

豆包针对 Agnes 的分镜规划对比、新模型接入、WorkBuddy 新 Skill 研究都不作为开工条件。先把自己的系统修顺，后续再做规划与模型的区分实验。

## 4. 必须保留的工作约束

1. 六个正式 Agent 的真实 ID 从当前注册表确认。预期职责为 Producer、编剧、角色资源、场景、导演、装配；Visual Review 先复用现有能力，不另建第七个常驻 Agent。
2. 当前免费主链与 Token Plan 是生产前提。核对真实配置和实际可用模型，不以历史型号或官网介绍替代本地能力；不得自动换收费模型。额度充足，测试次数由证据需要决定，避免无限重复同一种失败。
3. 所有适用文本及视觉模型调用保留 Thinking，并核验真实出站请求，包括重试、复杂意图解析和审查路径。不得靠关闭思考模式制造提速。
4. 新生成分镜视频源素材至少 8 秒，默认 10 秒，在当前合法时长范围内执行。成片保留时长单独决定。当前入口无法满足时，先修兼容性，不静默改成短素材。
5. 默认无旁白、无主动 TTS；保留合格原生环境声和音效。人物对白只保留既有剧情中确有需要的内容，单独标记风险，不能为本轮另加配音工程。
6. 继续区分候选推荐、用户审美接受、正式选片与 final_render。自动技术筛查不能冒充用户批准。允许在既有机制下生成审片候选，但不得绕过人工 gate 或改写正式版本。
7. 测试要走用户实际使用的正式入口。Claude Code 可以修代码、搭测试和核证据；六个系统 Agent 完成创作与制作。执行侧直接提交的生成必须单独记为人工介入，不能算 Agent 自主完成。

## 5. 自主修复权限与结束条件

Claude Code 可在现有职责和权限内，自行定位及修复完成判据、任务恢复、轮询、限流调度、状态投影、重复读写、上下文冗余、素材缓存、装配重复渲染及相关 Skill 接线缺陷。具体方案由真实证据决定，不要求照搬本文的字段名或假设。

每项改动留下“证据—改动—验证—剩余限制”。优先修当前损耗最大的少数环节。暂不扩大并发、重写六员体系、增加画布节点类型或接新服务；历史并发能力保持当前设置，不能反向强制为一条在途任务来制造新瓶颈。既有 OCC、版本和权限不得因提速而弱化。

本轮完成意味着：有真实可测的效率改善；没有通过削减剧情或质量检查换速度；克苏鲁追船已交出完整、可播放、经过系统审查的候选；首次失败、返工和剩余问题可追溯。用户尚未看片时，只能写“技术与自动审查通过／待用户看片”，不能写“用户验收通过”。

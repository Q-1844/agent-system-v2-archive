# Phase 53｜效率、协作与 Producer 扩权测试

状态：待 Claude Code 在真实项目执行。此包是测试任务书，不是测试通过报告。

## 本轮要回答的问题

保留目前六员体系及项目事实底座，通过新作品观察真实生产效率；另做 Producer 直接加载 Skill 执行的对照，判断交接减少之后，质量、恢复、上下文负担和人工介入是否发生变化。本轮先积累证据，正式系统优化和规则转正放到结果评审之后。

六个业务角色沿用此前确定的 Producer、编剧、角色资源、场景、导演、装配。准确 ID、工具、正式 Skill 数量及版本，由当前注册表核验。视觉审核沿用现有能力，不新增第七个业务 Agent。

此前结论支持继续使用现有协作底座和 Agnes 的候选适配策略，尚不足以证明协作模式最优或端到端已提速。此前曾有报告计数与账本计数不一致；本轮从真实任务、回执和版本重新对账，不沿用旧汇总作新基线。

## 执行环境与分工

| 对象 | 本轮职责 |
| --- | --- |
| Claude Code | 在项目仓库核验入口、准备隔离测试、启动和观察、取证、复算、出报告 |
| 系统 Producer 和专业 Agent | 通过产品正式入口自主制作；属于被测对象 |
| 用户 | 给审美反馈、处理系统已有的必要人工 gate、最终看片；本文件已授权测试范围内的启动与生成 |
| WorkBuddy / CodeBuddy / Grok | 本轮不作为执行依赖；其他测试可独立进行，避免共用配额干扰对照 |

Claude Code 使用客户端当前实际选定且可用的模型，记录版本，不指定未经核验的型号。系统内部文本、视觉、图片、视频模型全部冻结在当前验收基线；适用调用保留已获授权的 Thinking 配置，并检查实际请求。免费生产主链沿用现有政策，不自动换收费模型。

Claude Code 不代替系统 Agent 逐镜挑方法、补交视频、写生产 canonical 或代选片。外部脚本用于日志提取、复算、数据核验，不能成为隐藏的第二套制作器。

## 测试范围

允许新建测试项目、调用现有生产工具、保存候选和报告、复制批准素材、使用现有测试夹具与测试专用配置。只在现有入口支持时，用可撤销的测试会话配置给 Producer 授予明确的业务操作能力；记录差异，结束后撤销。

本轮不重构生产代码，不修订正式 Skill，不改全局权限，不删除角色，不建设新并发框架。为取证写的小脚本放在独立测试目录。缺陷进入问题清单；若缺陷妨碍实验，保留失败和现场，继续不依赖该缺陷的测试，勿边修边把修前修后拼成一次通过。

生产流程要求的人工 gate 仍然生效。自动放行、审核标准、返工上限和选版规则，两个模式完全相同。不得为提速跳过这些要求。

## 样本与工作量

三种故事各做一部现有模式的探索基线。每部以六个镜头为测试负荷目标，这是夹具设计，不是正式 Skill 的全局镜头数规则。若故事确需增减，由 Agent 在生成前提出并冻结；变化后重新复算预算。

室内剧情另做三个配对区组，每个区组 A、B 各一个独立运行，共六部。首个区组用于可行性观察；只有版本和条件完全未变时，它才可计入三个区组。探索基线不计入配对样本。

按每部六镜计算，核心计划合计九部、五十四条初始视频请求；不含资源/首帧图片、返工、能力探针及可选迁移测试。先确认当下可用配额，分批执行，勿把历史某天额度已满套到今天。配额不够时保留完整区组和未完成项，不减少 B 的镜头负荷来凑通过。

影片以短而完整、可评审为目标，成片约三十至四十二秒。源素材时长按当前用户认可的正式策略冻结；检查最近短段策略是否确已获准覆盖早前的至少八秒政策。无覆盖证据时仍采用至少八秒，不能自行换短段后把差异算作扩权收益。A/B 逐镜时长向量一致。当前模型不支持某时长时先如实报告兼容问题。

完成核心测试后，可按相同规则补一个要塞配对、一个怪物配对，作为跨题材探索，另增加四部、二十四条初始视频请求。它们不自动等同于长期稳定性证明。

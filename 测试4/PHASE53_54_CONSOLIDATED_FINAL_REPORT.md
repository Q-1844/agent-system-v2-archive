## 二、核心结论（数据支撑）

### 2.1 质量：六员链是唯一达用户基线的模式
- 六员链 3/3 通过（F/M 拿「好」）；四种新模式 0/4 通过（B1 勉强通过但叙事不可读）。
- **质量分水岭=独立审核在环+场景参考强制链**，不是执行架构本身。
- **根因（机制级，用户判读与数据互证）**：
  1. **场景参考链**：六员链的 BOUND 路径强制把场景系统参考图（sciv）塞进视频生成参考链——这是「衔接极好」的唯一来源。新模式的生成调用没带场景参考，**场景漂移是模型级倾向，文字约束与预铺锚点都钉不住**（M5 反证：预铺的 approved 锚点照样没用上）。
  2. **人物纪律有确定性机制**：`population_constraint` 人数排除子句（prompt tail）真实有效（M5 人物达标 vs B2/B3 失败）——「数得出」的约束可用文字钉，「长什么样」的约束只能靠参考图。
  3. **单 Agent 自审把关力弱于独立审核在环**：B2/B3 的分身缺陷，自审全部放过；执行侧终审也曾低估（校准教训：人数纪律违规=一票否决）。

### 2.2 速度：新模式架构优势真实，但未兑现为质量
- 速度排序：④主执行 **1.74h** < ③预铺+主执行 2.87h < ①六员链 4.7h 均值 < ②单 Producer 5.4h（含事故）。
- 提速来源=消除审核卡停等+节点编排+delegate 往返（认知开销），**不是生成加速**（provider 视频延迟是硬底，占墙钟 5-6 成）。
- 文本消耗只有六员链的 1/4~1/3；视频额度每片 83-104s（各模式持平）。

### 2.3 用户假设（下一战役待验证）
- **「可能是时长太短导致的」**——30-42s/六镜格式中场景建立与衔接问题被放大；下一步可用同方法生成 2-4 分钟长片（12-20 镜）验证。
- 样本量：每模式 n=1~2，全部结论为「方向性证据」；系统化后的批量对照才能出统计结论。

### 2.4 新发现的系统缺陷/风险（全部留档）
1. 修复完成契约 prior-credit 豁口（已修 A2）；终审卡无重开路径（已修 A3）。
2. 分镜层写 `negative_prompt` 字段会被视频 2.5 契约拒绝（INT-B4-02 桥接；producer 侧普遍风险）。
3. 单会话 467k/524k token 上限——模式②必配会话接力（session-split）。
4. 机器休眠 3.5h：watchdog 作废卡死任务+自动补交（零数据损失；建议关睡眠）。
5. 叙事可读性新缺陷类型：镜头全对但故事讲不清（B1）。

## 三、下一战役选项（按建议优先级）

1. **协作模式注册表系统化**（用户方向）：四模式+组合配方做成可配置档位；**硬规格=任何模式强制保留场景参考链+人数子句+独立终审**；统一跑分/终审/评审接口——批量对照出统计结论的前提。
2. **时长格式实验**：同方法生成 2-4 分钟长片验证用户「时长太短」假设（建议首验）。
3. **审核优化工具化**（当务之急的下一层）：执行侧终审的抽帧/人数/门连续性检查自动化，形成机器初筛+人终审。
4. B 批 scoped grant 转正评估（模式④生产化前置）。

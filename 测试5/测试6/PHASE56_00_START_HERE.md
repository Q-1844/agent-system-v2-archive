# Phase 56 效率与无人值守专项

状态：供 Claude Code 在真实项目实施与测试，尚未执行。

## 本轮已确定的选择

- 优先缩短单片等待时间，同时减少用户和执行侧的手工推动。
- 一台机器、同一时刻只运行一个项目。多个故事和克隆项目顺序执行；项目内部允许专业任务、独立镜头与审核并发。
- 将现有“组合预设”的本轮版本设为实验默认：按需专业预铺、Producer 主执行、困难上交、独立机器审核与有界自动修复。准确 mode ID 读取注册表，不另造同名体系。
- 沿用“全部做完再给用户看”。例行剧情细化、测试素材审查和范围内修复由获授权的机器路径处理；用户最终看片接受单独记录，不能伪造。
- 画面表现是附带观察；输入、版本、依赖、重复提交和流程停滞是系统问题，仍需修复。

本轮是上一阶段工程的收口和实测，不重新设计六员体系。默认模式按用户本次选择改为 Producer 实验组合，六员预设作为显式可选的对照与回退项。

## 项目与比较范围

| 项目 | 风格与剧情 | 核心测试 |
| --- | --- | --- |
| P1 断电前的证词 | 写实 悬疑交流与证据交接 | 固定组合预设，比较视频在途上限 |
| P2 铁门后的信号 | 写实 科幻要塞突入 | 固定并发，比较六员与实验组合 |
| P3 静默隔离舱 | 动画 空间站事故与撤离 | 自动接力、在途恢复、无人值守闭环 |

故事不是乡村日常或寻物散步。系统可发展台词和镜头语言，但不能删掉规定的动作、交流和依赖来省时；对照开始前冻结实际剧本、分镜和素材。

核心计划的初始视频需求为 376 秒。若其余预设支持一镜最小冒烟，另需 24 秒，共 400 秒；以实际可用 500 秒为示例，可留 100 秒给返工。图片、文本、失败提交和更大的最小模板另算。预算不够就按已授权范围分配额周期续做，不改负荷造通过。

## 这轮怎样算有进展

分别判：机制是否接通、真实独立任务是否重叠、单片历时是否改善、是否减少人工救援、候选画面与用户反馈。系统工程可以通过而画面仍有不足；失败成片也不能被快速标为成功来抬高效率。

不预先承诺并发翻倍或某固定提速幅度。先交首轮原始结果，继续完成可独立推进的任务；普通实现与测试已有授权，不每切 Skill 或每开始一片都询问。

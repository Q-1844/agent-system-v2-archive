# Phase 56 A 机制收口与实验默认

## 目标与边界

围绕 Phase55 已报告的缺口做最小修复，使已有模式和并发能够真实使用。允许后端、必要前端、定向测试和配置修改；不重建存储、框架或通用工作流引擎，不新增一批业务角色。

先核验 `collab_modes.py`、`video_contract.py`、`input_manifest.py`、`JobQueue`、`master_lease.py`、`handoff.py`、`review_pipeline.py`、现有工作流和产品面板的真实路径及当前状态。已修好的项以测试确认后跳过，不重复实现。

## A1 实验默认与授权

把既有组合预设的新版本设为本轮实验默认。内容为：按需预铺 → Producer 获 scoped grant 主执行 → 明确专业困难上交 → 独立机器审查 → 上限内局部修复 → 固定选版清单装配。

显式保留六员、单 Producer、预铺、上交等已有选择。默认只作用于新启动的实验运行；旧项目和在途 run 继续使用原快照。不因改默认重写已有选片或项目策略。

机器按本次用户授权处理测试范围内的例行素材、检查和有界修复，全部保留 actor、授权来源和审查记录。后端如有专属用户权限，须接合法的代理审核能力，不能用管理员、SQL、伪造 user 身份绕过。最终“用户接受”仍等待用户看片，不由机器填写。

实验默认实际应用后的 mode/config/Skill/model 哈希须写入 run，正常入口可查看。不能只在启动提示词中说已使用组合模式。

## A2 参考与接续规则收口

修复“bind 已有但场景仅 context_only 仍算视觉消费”的歧义。输入清单区分：原生视频参考、经 full 首帧制作间接输入、文字上下文、未使用、显式豁免；记录具体资产和版本。

基线等价政策下，必需的场景/身份视觉依据要真正进入合法生成链；不允许以文字提及冒充传图。槽位或模式不兼容时选择已支持的合法路径，不能静默丢图或添加非法参数。

连续性按三种语义处理：

1. 同一动作真实继续：声明对已选上游实际裁切末帧的硬依赖，等必要审查、选版和端点就绪。
2. 同场景换机位/正反打：可重建首帧或正常切镜，保存人物位置、道具归属和初终状态依据。相邻镜不因此自动成为媒体硬依赖。
3. 换场/时间跳跃：按批准故事建立新镜，记录切镜理由；不为了画面相似强行插桥。

可沿用 `reference_policy v2` 的命名，但不要把所有同地点镜头强制串成尾帧链。依赖的增加必须来自真实制作需要，否则会直接损害本轮提效目标。

## A3 恢复与主控的前置修复

- 已知 Provider task ID：watchdog 延长用尽或轮询出错后，重试仍先查询原任务。不能从 FAILED 直接走新提交。
- 提交结果不明：保存逻辑请求意图和输入依据，优先对账。无可靠查询/幂等能力时进入明确待核验状态，暂停该项新提交；`previous_submit_uncertain` 只是标记，不是自动重发许可。
- 同一 Provider ID 的重复收货去重，与“同一逻辑请求又生成了不同 ID”分别检查。
- 主控租约损坏不再 fail-open 放行新的派发和项目写入。恢复读、查询和接管有独立路径，权限未核明时不能双主推进。
- 一个项目只有一个主控；视频 worker 可并发。查清普通镜头更新的锁范围，覆盖读改写临界区，旧结果到达时复核输入 basis。不能泛称所有入口都有 CAS。
- run 达到自动接力上限仍有工作时，状态应是待接力/未完成，不能仅加字段后标完成。

保留 scoped grant、repairRequireNew、审核卡指纹与 refresh 语义。不得为少阻塞移除守卫。

## A4 让并发配置实际生效

核对 run 的 `media_inflight`、config 的 `video_inflight`、环境变量和真实队列容量之间的映射。只保留一个明确的最终解析结果，并记录实际生效值及覆盖来源。

若现有队列只能启动时设 worker 数，先用“上个运行和在途任务结算后重配/重启”的可靠方案；重启时间单列。不要把记录在快照中的数字当作热重配已完成。需要热重配时再做有测试的最小实现。

确认就绪任务能被及时提交，不必每次等待 Producer 再思考确认。无完整依赖队列则补齐最小就绪推进能力，复用现有账本、锁与生成工具，不复制第二套状态。

限流与在途容量分开：真实账号共享的请求桶、轮询预算、每日额度均核对。解析实际 Retry-After 并有界退避；不因并发调大制造重试风暴。

## A5 无媒体费用验收后冻结

先验证：默认选择与快照固定、不同角色的输入契约一致、正常切镜合法、真实尾帧依赖不提前、重复领取/收货、未知提交不盲重发、watchdog 超限续查、损坏租约拒写、旧会话晚返回、接力未完成状态、自动修复确有新产物。

针对修改路径做定向测试与项目要求的回归。补上轮测试计数及未回填的全量结果，按失败集合与基线比较，不只比数量。

冻结代码、正式 Skill、参考/审核/修复政策、模型、账户/限流设置和实际并发解析逻辑。交 `PHASE56_A_MECHANISM_REPORT.md`，附版本、diff、正常入口截图或调用证据、测试与剩余阻塞。A 后只读取证不改规则；新修复需新版本批次。

# Phase 56 D 无人值守与恢复闭环

## 主要目标

减少用户和 Claude Code 手工推动。例行制作、检查、上限内局部修复、复审与候选装配应由正式系统闭环完成；最终给用户看完整结果与问题清单。

现有组合预设只在生产结束后终审、随后交用户或下一 run 决策，不能算自动修复已完成。本批补最小闭环，不新增复杂审美评价体系。

## D1 自动检查与有界修复

沿用当前已代码化的硬维、合法人数/非人角色清单和固定抽帧政策。计划相关关键动作补必要帧，不把单帧抽检写成全视频无错保证。各对照组相同。

轻微质感、表演和口型问题记录，不增加无休止修复。明确硬错沿现有 repair_scope 只修错误镜及真实依赖；保留 repairRequireNew，旧候选不能冒充本 attempt 新结果。

修复 → 新候选 → 绑定版本和裁切的复审 → 规则允许的机器选版 → 固定清单装配。复用有效审核仅限同版本、同区间、同政策。不得改已决策卡内容后沿用旧决定。

沿用现有每镜返工上限；同时受剩余额度限制。达到任一上限，记录明确失败/待处理状态，交已完成内容和原因，不继续无限尝试。可以输出正式路径支持的实验预览，但不能把硬错版本标批准或绕过装配 gate。

用户接受状态只能由用户反馈回填；机器完成与用户通过分开。范围内机器审批和修复已有本次授权，无需再逐镜询问。

## D2 确定性推进与接力

输入与计划明确的排队、查询、收货和状态推进由程序处理，减少每步都让模型重读全项目。只有策略选择、异常诊断和专业上交进入 LLM 决策。

token 监控采用实际请求预算及 usage 锚点，包含系统/工具/Skill、历史、媒体估算与输出预留；成本累计另记。优先裁剪无用回执与按需读引用，不只靠不断开新会话。

自动接力保留同一个逻辑 collab run：交接包保存 canonical 索引、已选版本、在途任务 ID、待审/失败、grant 和下一步。新会话回读真相并合法续接授权；旧会话不能再主控写入。达到接力次数上限仍未完成时，明确待接力，不标成功。

## D3 P3 的真实演练

一次运行内按条件安排，先在无费用夹具走通，再进入真机：

1. 通过正常产品入口启动 P3；使用 B 批合法候选档位，确认多个输入就绪。
2. 至少两个独立视频任务已取得并持久化 Provider ID、仍有工作未完成时，触发测试用低阈值自动接力。不能靠 Claude Code 新建 run 手工续做来冒充自动接力。
3. 条件允许时，在某个已知 ID 仍在途时受控重启服务/客户端。恢复沿原 run 与任务查询、收货，核对没有对同一逻辑请求新建另一任务。
4. 重复完成观察/通知应只正式收货一次；保留实际版本与有效指针。
5. 自动继续检查、修复与装配；因额度或硬错误不能完成时诚实报告，不伪造连续成功。

这次故障运行的历时独立报告，不与 B 的正常并发速度混算。用户无法提供实时干预也不应让测试者偷偷补交。

## D4 只用模拟或回放的故障

提交不明、断网黑洞、Provider 未确认取消、租约文件损坏、乱序/旧版本回执、并发写冲突等先用现有夹具验证。不要通过真实断开付费提交来制造不必要的重复消耗。

提交不明优先对账；无可靠证据时保持待核验，停止该项再提交。其它已就绪工作可在同项目继续；若账号在途容量和额度无法结算，暂停新的媒体派发，离线诊断继续。

## D5 人工介入与验收

分别记录：启动与素材准备配置、测试设定的故障操作、用户例行看片、系统故障救援。人为触发重启不是救援；重启后人工补任务/选方法才是救援。

交 `PHASE56_D_AUTONOMY_RECOVERY_REPORT.md`，列自动完成的阶段、接力次数、原任务 ID 的延续、重复提交核对、修复范围、新成果、剩余边界及所有救援。

成功应有实际操作轨迹；“没有 blocker”“没有问用户”不能单独证明闭环可靠。受阻也交出问题发生处、保留成果与可继续状态，不能把未做步骤写成通过。

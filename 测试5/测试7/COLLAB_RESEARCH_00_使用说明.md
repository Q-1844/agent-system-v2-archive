# 协作架构深度研究交接包｜使用说明

日期：2026-10-18。性质：研究准备材料，不是架构定案或工程开工令。

## 1. 这次要解决什么

目前需要弄清楚：在一台机器、一个活跃制作项目的条件下，怎样组合 Producer、专业 Agent、Skill、程序调度和独立审核，才能缩短单片等待、减少人工推动，同时保住输入依据、版本、授权和恢复纪律。

这轮先研究，不继续消耗视频配额。研究结论经过用户讨论后，再交回当前对话审查，最后另写实施方案。

## 2. 建议顺序

1. 把 `COLLAB_RESEARCH_03_CLAUDE_CODE_只读取证打包.md` 交给能访问真实仓库的 Claude Code。让它只读核验、整理已有证据，不生成视频、不改系统。
2. 新开深度研究对话，把 `COLLAB_RESEARCH_02_深度研究执行提示词.txt` 的全文作为任务提示词。
3. 同时附上 `COLLAB_RESEARCH_01_系统现状与研究问题.md`、原始 `01-PHASE56_COLLAB_FRAMEWORK_PROPOSAL.md`，以及 Claude Code 产出的核心证据 ZIP。
4. 阅读研究报告后继续讨论。把最终报告、仍有分歧的问题和补充证据交回本对话，再评判推荐结构与实施批次。

核心 ZIP 尚未准备好时也可以先研究，但只能形成条件性方案，不能声称完成了源码核验。先整理材料更有利于判断提案中的关键因果关系。

## 3. 四份文件各自做什么

| 文件 | 用途 |
| --- | --- |
| 本文件 | 交接顺序与当前阶段边界 |
| `COLLAB_RESEARCH_01_系统现状与研究问题.md` | 用户目标、系统基础、已知问题、最新提案及证据缺口 |
| `COLLAB_RESEARCH_02_深度研究执行提示词.txt` | 可直接复制给研究 Agent 的完整任务 |
| `COLLAB_RESEARCH_03_CLAUDE_CODE_只读取证打包.md` | 在真实仓库收集源码、配置、报告和脱敏运行记录的执行指令 |

四份文件独立提供；它们本身没有被藏在压缩包里。后续 ZIP 用于承载必要的源码和证据。

## 4. 当前材料的可信范围

本次直接读到的报告是 Phase54 报告、Phase55 实施报告及附录、Phase56 协作框架 v3 探讨稿；还复核了本对话生成的 Phase56 执行任务书。

**这次没有拿到 Phase56 A/B/C 正式报告、原始时间线或当前仓库。** 因而“1/2/3 路真实并发、13 次拒绝、650 秒延误、六员慢 2.7 倍”等数字，当前只能写成“探讨稿报告的观察”。它们不是本次独立复测结果。D/P3 的当前进度也应由取证包说明。

研究者应先核验这些观察，再解释原因；不能把旧任务书里的待办当作已完成，也不能把新提案里的设计当作已落地。

## 5. 这次不必先追问用户

研究目标和主要约束已经足够明确，可以直接准备取证和启动研究。以下事项留给研究之后讨论：是否引入子 Producer；专业角色如何保留；需要何种候选提交与合并机制；是否值得更换存储或调度框架；能接受多少文本/视觉调用来换取时间。

研究者应先给出带证据的选项、推荐和反例，再提出会改变选择的少量问题。不要一开始让用户猜子 Agent 数量、扫描周期或重试次数。

## 6. 本次交付完成标准

研究报告要能回答：慢在哪里、哪些判断确实需要模型、哪些工作应自动推进、不同角色如何并发而不互相覆盖、断线后如何避免重复消耗，以及最小的下一轮验证是什么。暂不要求写实现代码，也不承诺某个固定提速倍数。

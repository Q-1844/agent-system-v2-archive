# Phase 56 B 单项目内并发主试验

## 固定条件

使用 P1《断电前的证词》的批准工作包，五镜，每条源视频固定 8 秒。镜头 1→2 有真实裁切尾帧依赖，其余镜头按批准状态准备独立输入；故事时间顺序与媒体依赖分别登记。

使用实验组合预设，固定模型、画幅、正式 Skill、场景/角色/道具参考、生成模式决策、审查位置、修复上限、裁切规则和输出目标。只改变视频在途上限。批准资源的预铺成本另列，不让某组重做素材、另一组直接复用。

若 8 秒当前不可用，生成前统一修订整组时长及预算，不能只缩短一个档位。各次运行从同一批准快照新克隆；被测视频输出、选版指针、审核状态与“已完成”标记不继承。基础参考可以只读复制。

## 两轮排期

| 轮次 | 顺序 | 初始视频请求 |
| --- | --- | --- |
| 首轮 | 上限 1 → 上限 2 → 上限 3 | 各五条，共十五条 |
| 第二轮 | 上限 3 → 上限 2 → 上限 1 | 各五条，共十五条 |

一个运行及其在途任务结算后再启动下一项目克隆；不同时跑不同档位抢同一限流池。两轮之间可以安排其它项目，但不得改被测版本；记录日期/时段与服务异常。较高档位账号不支持时如实受阻，不更换账户或绕过限制。

首轮先交原始结果，后续按总控排期完成第二轮。两轮只是探索复验，不宣称统计显著。出现规则或代码修改，旧轮保留为发现样本，新版本重建匹配比较，额外消耗转到预算表。

## 必须证实三件事

1. 所选档位真实作用于执行队列；快照、全局参数、环境覆盖和运行日志一致。
2. 独立任务确有在途时间重叠，且 1→2 依赖未被破坏。容量增加但上游仍逐个等待时，定位是未派发、限流、材料未就绪还是 Provider 排队。
3. 同等负荷和相同机器检查政策下，实际等待或人工推动改善。并发无收益也可成为有效结果，不通过删镜、少审、缩短片段或混入缓存命中制造提速。

## 计时与自主性

- 主指标：批准输入就绪到完整候选达到机器基本检查终态的历时；成功、修复上限失败和其它中断状态分别列。
- 辅指标：全部初始任务收货时间、就绪至提交、Provider 可见时间、收货/审核/装配时间、重试和修复、文本/视觉调用、人工救援次数及有证据的劳动时间。
- 资源冷启动耗时与本批暖启动制作耗时分开。人工“等回复”与实际劳动不混同；用户已授权机器完成例行环节，不额外加入逐镜人审。
- 完成在途观察有轮询精度限制；无服务端完成事件时给观察区间，不假称精确延迟。

错误候选按相同机器硬错检查与有界修复处理。模型画面失误不自动否定队列是否正确，但失败不能进入“成功影片更快”的速度子集；同时给全部运行的失败分母和时间。

禁止 Claude Code 外部补视频、改 canonical 或手工挑技术路线后冒称无人值守。若救援不可避免，保留中断现场，标为救援运行；继续能独立推进的任务。

## 候选档位选择

看两个轮次的原始值与一致性，并同时看额度、错误和人工介入；不仅挑最快一条。较高并发无稳定收益时可选较低档。结果先记为探索候选，交给 C 批跨剧情观察，不能称长期最优。

交 `PHASE56_B_CONCURRENCY_REPORT.md`：六个 run 的快照、实际容量、时间线、产物、失败/救援、逐档结果和建议。若第二轮未做完，明确部分完成，不把一轮写成复验通过。

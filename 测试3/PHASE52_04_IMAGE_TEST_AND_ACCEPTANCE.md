# 图片与系统效率测试、验收要求

客户端：CodeBuddy。按真实代码运行有意义的测试，不仅检查文档。视频配额不足的本轮不提交新视频；用已有素材和隔离故障环境覆盖恢复逻辑，分别注明真实、重放和模拟。

## 固定比较条件

记录基线 commit、候选 commit、模型、思考模式、任务、参考哈希、审核政策、硬件与启动状态。首次生产、缓存复用和故障恢复是不同组，不混算。

使用克苏鲁追船的实际已批准内容。图像测试至少覆盖角色身份、船与环境、双人同框，以及已有上游输入的下游构图；没有相应历史素材时创建独立图片测试项目，标明新输入。

生成前确定同一任务负荷和验收标准。优先用现有完整日志或受控回执建立工程基线，再做真实图片复验；无需为每个故障场景消耗一次图片生成。

## 必测行为

| 编号 | 场景 | 预期行为 | 证据 |
|---|---|---|---|
| E01 | 合格成果存在，本次没有新写入 | 当前版本核验后完成或复用 | 原 receipt、版本、当前完成状态 |
| E02 | 成果已过期或参考被替换 | 不误复用；只处理相关依赖 | 输入哈希、stale 状态、影响范围 |
| E03 | 已受理任务后观察中断 | 恢复原任务，继续收货 | 相同服务端任务标识 |
| E04 | 提交超时，受理状态未知 | 核对或显式 unknown，不盲目重交 | 受理查询、幂等证据或未确定状态 |
| E05 | 首次明确失败，修正后重试 | 新 attempt，保留旧失败 | 请求差异、失败记录、选版 |
| E06 | 重复成功回执 | 不重复推进或覆盖选版 | 去重记录、前后任务状态 |
| E07 | 旧 attempt 晚到 | 归档，不覆盖当前候选 | attempt、revision、选中版本 |
| E08 | 浏览器刷新和新会话 | 从持久项目状态恢复 | 项目读取、未增加生成提交 |
| E09 | 后端重启 | 恢复队列、在途任务与待处理状态 | 重启前后快照 |
| E10 | 上游更新导致 OCC 冲突 | 拒绝错误覆盖，重新核验当前输入 | 冲突与版本记录 |
| E11 | 输入就绪、额度允许 | 已确定步骤及时推进 | 就绪、提交和等待原因 |
| E12 | 上游、真实端点或人审未完成 | 保留等待，不越过前置条件 | 依赖与审核记录 |
| E13 | 多观察者查询同一个 job | 去重，恢复不创建重复观察任务 | 查询计数和观察者状态 |
| E14 | 本地限流与上游 429 | 分别识别来源，遵守总额度和退避 | 错误来源、Retry-After、重试 |
| E15 | 参考 URL 失效或托管失败 | 定点修复，不重做无关内容 | 原图哈希、可达性、恢复结果 |
| E16 | 已选视频的裁切终点改变 | 检查相关接力帧及下游依赖 | 已有素材、裁切及端点记录 |
| E17 | 相同失败反复发生 | 按现有修复上限结束或换策略 | 同类错误、尝试与结束状态 |
| E18 | 未绑定、绑错或漏加载 Skill | 发现实际加载差异，不冒充测试成功 | 绑定、加载文件、哈希 |
| E19 | 视觉检查只给了路径、没传图片 | 审查无效，补传实际图片 | 请求输入与审查证据 |
| E20 | WorkBuddy 与本地系统疑似共享额度 | 未查清前不同时生成 | 非敏感账号标识及调度决定 |

E03/E04/E06/E07 等故障注入应在隔离环境操作，不能污染生产 canonical。模拟不能代替当前真实图片链路的成功证据。E16 使用已有视频，验证依赖机制；不是新视频视觉效果测试。

## 真实图片复验

分别完成船长、大副、双人船上画面，以及从合格上游构图继续下游画面的链路。参考图尽量复用当前已批准素材；需要新建参考时记录并保持比较一致。

检查人物身份、环境连续性和重大不合理；调用支持图片输入的视觉模型，证据覆盖实际上传、图片对应版本及输出。生成是否成功、审核是否通过、是否选用分别记录。

对耗时做固定条件的多次复验，保留每次结果及波动。数量由日志可信度和故障重现情况决定，不为了凑次数反复消耗额度。上游时延变化明显时，单独比较本地可控部分。

## 计时计算

对同一个 run：墙钟时间是终点减起点；某阶段忙碌时间是该阶段活动区间的并集；必要等待、人工等待和无法解释的空档单独标记。活动累计时长可大于墙钟时间，不可将两者混用。

只有可比基线大于零且候选数据完整时才算缩短比例。基线缺失、区间倒置、时钟无法对齐或计时中断时，报告数据问题而非提速百分比。

## 结论状态

| 项目 | 通过条件 | 限制 |
|---|---|---|
| 系统逻辑修复 | 重现问题已修复，相关边界与回归通过 | 未重现问题不算已修 |
| 图片链路 | 真实生成、收货、检查、选用可追溯 | 不代表视频画质 |
| 工程效率 | 相同口径证据解释改善及代价 | 服务波动时不承诺整体倍率 |
| 视频恢复逻辑 | 真实历史任务或隔离模拟边界通过 | 注明是否使用真实在途任务 |
| 完整视频提速 | 本轮不作该项通过声明 | 后续可比新视频测试再验 |

输出 PHASE52_IMAGE_AND_RECOVERY_RESULTS.md，每个场景写执行环境、证据、是否通过、是否模拟与未解决问题。最终报告逐项给结论，不能用一句“全通过”掩盖尚未执行项。

# 双客户端同步与比较规则

## 唯一写入职责

CodeBuddy 负责我们的生产仓库、效率修复与本地项目状态。WorkBuddy 负责自己的测试工作区和创作平台项目。冻结交接目录只读。不同分支也不意味着可以同时修改同一个运行中的项目数据库。

共享素材使用独立副本与哈希，避免某一边“修好了图片”却让另一边基线无声变化。共同文件通过新增版本交换；不覆盖正在运行的基线。

## 阶段安排

| 阶段 | CodeBuddy | WorkBuddy | 等待条件 |
|---|---|---|---|
| 初始化 | 仓库核验、基线计时、提取正式 Skill | 工具、平台、账号及额度核验 | 两边可立即启动 |
| 输入冻结 | 提交基线清单和原文副本 | 阅读交接、验证哈希、建立适配记录 | 视频主测试须有真正 Skill |
| 各自执行 | 代码修复、恢复测试、真实图片测试 | 独立视频制作、审查、局部修复与导出 | 各自输入与额度满足 |
| 结果反馈 | 提交系统报告，评估建议 | 提交成片、全过程和建议 | 可先交各自结果 |
| 汇总 | 同口径解释工程改善 | 解释视频优势或失败来自哪里 | 不强求互相等到全通过 |

不需要实时互相修改。建议的交接点是冻结输入、首次候选完成和最终报告提交；发现共享资源冲突或严重错误时及时同步。

## 生成请求能否同时执行

| 资源状态 | 可否同步生成 | 做法 |
|---|---|---|
| 独立账号、配额和平台项目均已核实 | 可以 | 各自遵守真实服务限制 |
| 同一账号或 Key，共享配额 | 默认不同时发起 | 指定一个生成调度方，按现有串行上限安排 |
| 是否共享未知 | 暂不同时生成 | 先核验；只读与本地测试继续 |
| 我们的视频配额不足，WorkBuddy 有独立可用视频额度 | WorkBuddy 可继续 | CodeBuddy 只做本轮图片和系统测试 |
| WorkBuddy 额度不足 | 视频测试待处理 | CodeBuddy 继续；WorkBuddy 做输入与工具准备 |

“两个客户端同时开展”与“提高我们系统的生成并发”是两件独立工程安排。本轮不扩大系统并发。

## 可比较的层级

| 标签 | 前提 | 可以回答 |
|---|---|---|
| 同分镜跨平台测试 | 剧本、分镜、Skill 与关键输入冻结一致；平台差异记录完整 | 相同创作任务在各平台的表现 |
| 自主规划独立测试 | 相同题目，按我们的实际 Skill 自主规划 | Skill 在外部平台能否落地并完整成片 |
| 同模型工程效率对照 | 修复前后同模型、任务负荷、输入、审核、硬件条件可比 | 可测阶段是否因工程改动缩短 |
| 部分可比测试 | 源镜时长、素材或工具约束改变 | 标明差异后的局部经验 |

WorkBuddy 一次成功不会证明我们的系统完全无问题；失败也不能单独证明我们的 Skill 无效。模型、内部 Agent、输入质量、人工介入和平台功能都可能影响结果。

本轮 CodeBuddy 未提交新视频，不能报告“本系统整条长视频已提速”。已在档视频可以用来讨论质量；旧耗时口径不一致时只能作背景。

## 效率与质量分开报告

效率看同口径墙钟时间、等待原因、重复请求、恢复成功、查询负担和人工操作。生成质量看人物身份、环境连续性、重大不合理、关键动作因果、有效保留区间及接缝。导出成功单独记录，用户看片单独记录。

平台只显示积分时，保留实际积分变化，不猜测折合金额。平台模型未知时写 unknown，不根据画风反推型号。

## 回传顺序

两边按各自执行书提交报告和文件。WorkBuddy 建议表须包含编号、证据、迁移前提、最小验证和风险；CodeBuddy 写采纳决定。候选 Skill 必须独立编号、独立哈希，不自动转正。

如果某边失败，另一边仍完成已授权且不依赖它的任务。必要输入缺失时如实标记等待，不能把等候时间称为工程空转，也不能用另一个默认 Skill 填空。

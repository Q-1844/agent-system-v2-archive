# Phase 46｜六个 Agent 工作流真实测试与验收流程

版本：v1.0；日期：2026-10-03。配套执行书：[PHASE46_01_SIX_AGENT_WORKFLOW_INTEGRATION.md](PHASE46_01_SIX_AGENT_WORKFLOW_INTEGRATION.md)。

**给 zcode 的目标：用真实页面、正式任务入口和系统 Agent，找到并修复接入缺陷，证明六个 Agent 能按用户画布流转，且任何等待、失败和恢复都可核验。**本文是待执行测试方案，没有预先判定任何用例通过。

## 0. 测试纪律与通过口径

### 0.1 额度与思考模式

额度充足，不因为费用假设缩减必要生成、候选比较、错误复现或新会话复验。遵守速率、队列和已有资源锁；每次真实生成留下要回答的问题，避免无法分析的重复调用。

所有真实文本调用使用当前统一 `agnes-3.0-flash` 且启用思考，包括六员、复杂意图解析、文本审核／诊断、工具结果回填、失败重试与恢复。首次和后续请求均检查出站 JSON，而非只检查配置。

确定性 schema／状态机故障注入可以使用受控假服务；标明 `mock/fault-injection`。**真实 Agent 接入、Skill 实际加载和成片 E2E 不能用 mock 或手工代写产物证明。**人工审核机制的自动化可用独立测试主体；不能把它冒充用户真实批准或定版。

### 0.2 分开四项验收

| 验收项 | 必须证明 | 不能替代它的证据 |
| --- | --- | --- |
| 软件接入 | 保存、校验、派发、交接、审核、状态、停止与恢复正确 | 截图好看、模型回复“已完成” |
| Agent 自主制作 | 六员在正式入口中各自执行职责，通过工具产出可追溯结果 | zcode 脚本直接生成项目事实或媒体 |
| 媒体质量 | 视频／旁白／音乐／剪接达到故事与观看要求 | HTTP 200、文件存在、编译通过 |
| 用户正式决策 | 资产批准、视频 select、最终 render select 由相应正式入口完成 | 测试账户通过、Agent 推荐、流程审核许可 |

### 0.3 每个测试结论使用明确状态

- `PASS`：本用例的全部判定满足，有可定位证据。
- `FAIL`：具体判定失败，附失败层和复现。
- `BLOCKED_INPUT`：缺少合法输入、Provider 权限或环境条件；不算通过。
- `WAITING_USER`：已有可审材料，等待真实用户决定；不算用户验收通过。
- `NOT_APPLICABLE`：确实超出首版范围，并说明依据。不能用来免除必需六员接入、双审核和已知提交恢复。

预期阻塞也是可通过的负例：例如无 Look 时成功阻止导演启动，**该负例 PASS 不等于导演制作能力 PASS**。

## 1. 测试前置与证据采集

### 1.1 冻结本轮环境

记录 git HEAD、未提交 diff 的摘要、六员 registry 与 Skill 版本、数据库迁移版本、workflow contract、Provider 适配版本、文本模型和思考配置摘要。保留真实配置的脱敏值，不保存 API key。

基线检查：前端构建与 workflow 类型检查；受影响的后端任务／委派／OCC／审核／Assembly 测试；必要时执行仓库正式全量回归。历史报告的“30 项真机”“2623 passed”只作比较线索，不当成本轮结果。

标明基线失败的具体用例、当前环境与是否涉及本范围。不能仅以“零净增”宣称正式路径可用。修复阶段做定向回归；完成所有实现后跑一次适当的完整回归。没有新改动／异常时不无意义反复全仓执行。

### 1.2 最少采集的数据

| 维度 | 必须保留 |
| --- | --- |
| 定义 | workflow ID、revision／hash、node／edge IDs、目标范围、Skill 绑定 |
| 运行 | run ID、启动幂等键摘要、版本快照、总状态、事件游标 |
| 节点 | node／attempt ID、正式 Agent ID、任务输入、完成条件、task／session refs |
| 模型 | 用途、实际模型／端点、出站思考字段、响应 ID、finish reason、可用 usage |
| 产物 | canonical ID／revision、媒体版本、receipt、basis／provenance、批准／select 状态 |
| 审核 | request ID、对象版本、主体、意见、决策及决策 receipt |
| 故障 | 注入点、请求是否已可能接受、进程状态、恢复动作、实际任务数量 |
| 浏览器 | 页面路径、截图／录像、关键网络结果、断线与恢复时间 |

证据以现有数据库、任务日志和工具回执为准；截图辅助判断。日志只记录必要请求元数据、工具参数和结果，不要求披露模型完整内部推理。

测试结果表每行包含 `case_id、fixture、trial、baseline、result、expected、actual、evidence_refs、bug_id`。每一轮都保留，包括失败轮；修复后成功不能覆盖先前失败记录。

### 1.3 隔离测试

使用独立测试项目、独立草稿和明确的 fixture 标识。不改写原《雨灯归航》或其他已有正式项目的 selected／final 指针。测试停止后仍保留必要任务和产物证据；不要为清理把 receipt 删除。

使用项目既有复制／测试夹具入口准备 canonical，不能直接改数据库绕过正式 ownership 来宣称制作能力成功。数据库只读核验可以使用脚本；必要的测试建模数据必须标注来源。

故障注入优先在测试项目和测试任务进行。后端重启应针对隔离测试服务，避免干扰已有真实生成。不能通过断开全部网络或杀死共享生产服务来制造复现。

## 2. 四类素材夹具

| 夹具 | 用途 | 条件 |
| --- | --- | --- |
| F0：纯草稿与无素材项目 | 保存、结构、前置条件负例、助手无副作用 | 不提交图片／视频生成 |
| F1：已批准素材的测试副本 | 装配入口、恢复、双审核、复用对照 | 正式选片／音频／资源版本明确；复制后保持来源 |
| F2：新作品《钟楼邮差》 | 六员真实新制作及完整交接 | 新项目，由系统 Agent 制作；关键素材与选片走真实 gate |
| F3：冻结后的未知新故事 | 新会话泛化与稳定性 | 只给作品目标，不提供上轮逐节点答案 |

### 2.1 F2 作品简报

一只穿靛蓝短背心的小狐狸，携带圆形铜色邮筒，从雨后的街角出发，把一封信送到钟楼门口；最后收信人取走信件，小狐狸确认投递完成。故事以动作叙事为主，无人物对白，可加简短旁白。

保留一个稳定角色 Look、一件重要道具和两个有区别的场景。由编剧决定两个故事段、三个到四个有意义的镜头，总时长约 15—25 秒。第一段应存在可检查的组内动作交接，第二段有真实换场。角色、道具、空间和“信确实交给收信人”的终态均可核验。

这是测试作品规模，不是视频方法答案。导演根据正式 Skill 与当前 Provider 自行选择独立起镜、参考、接续或其他合法路径；不预先指定每镜模式。不要为测试首尾桥强行给正片插入不必要镜头。

装配输出一个无声预览及一个带旁白／音乐的可审版本，二者通过正式 Sequence／render 链路形成。旁白至少覆盖三个叙事点；音量、音乐段落和原声处理沿用当前正式能力。语音／音乐资产引用和使用权限按项目现有机制确认，不重新搭建音乐生成平台。

### 2.2 F3 新故事原则

冻结后给出另一部小作品，角色外观、道具、场景与终态不同。例如“维修员取回一只迷路的发条鸟，并将其送回室内工作台”。具体镜头和方法由系统 Agent 规划。

新会话不能读取 F2 的逐镜正确答案或失败后定向指令作为完成提示；可以正常读取产品正式 Skill 和用户作品简报。外部测试驱动可以查看证据与断言，但不提前告诉执行 Agent 哪一镜应使用哪一方法。

## 3. 文本模型与思考测试 M

以下为必测项。调用真实 Provider 的项目级探针用于确认参数链，纯序列化单测用于补足边界覆盖。

| ID | 动作 | 通过判定 |
| --- | --- | --- |
| M01 | 六员分别执行一项职责内文本任务 | 六个实际模型均为当前统一配置；出站思考开启；返回与工具调用可处理 |
| M02 | 复杂组合语句走助手 Producer 解析 | 出站 `enable_thinking=true`；解析为合法意图；生产 task 数不增加 |
| M03 | 模型先返回工具调用，再回填继续 | 后续请求思考字段仍在；tool call ID／结果匹配，产物由正式工具产生 |
| M04 | 文本请求合法重试一次 | 重试不掉思考、不静默换模型；明确区分文本重试与生成重提交 |
| M05 | 从工作流检查点继续文本任务 | 使用该 run 的模型配置快照；思考继续开启 |
| M06 | UI 或 request 中试图关闭思考 | 真实测试运行入口拒绝不符合本轮配置的覆盖，或按统一强制配置执行并明确记录 |
| M07 | 流式响应含仅工具调用、空文本块或多段参数 | 不判空回复为成功；工具参数完整拼接且合法校验；思考不混入正文／JSON |
| M08 | 输出截断或 malformed JSON | 如实失败或受控修复；失败动作不列成功；不以空产物推进 |
| M09 | 适配链返回不支持思考参数 | 标为阻塞并修适配；不能自动关思考后把用例算通过 |
| M10 | Director 的视觉与文本分支并行检查 | 原视觉配置保持其正式范围，实际文本推理均走开启思考链 |

M01 至少核对每员的首次与一项后续请求。正式 E2E 轮次统计所有文本调用的启用覆盖率，要求 100%；返回 reasoning token 计数不是覆盖率的唯一依据。

对所有结构负例补充数据库／任务查询，断言 run 或生产 task 没有被错误创建。只看前端报错提示不够。

## 5. 六个 Agent 分别接入与职责测试 A

这些测试必须经过真实页面或正式 workflow API，统一任务适配路径不能另设测试捷径。先完成单节点／小链，再进入整链。

| ID | Agent／情景 | 通过判定与证据 |
| --- | --- | --- |
| A01 | Producer 为新项目制作计划／交接 | 正式 task、有效计划结果、输入引用；未越过后续节点或审核自动执行全链 |
| A02 | 编剧制作新故事与故事段 | canonical 实际增加或更新、revision／ownership 正确、工具 receipt 齐全 |
| A03 | 资源 Agent 制作角色 Look 与职责内道具资料 | 真实新产物／候选和 basis；待用户批准的状态没有被伪造 |
| A04 | 场景 Agent 制作两处场景事实与现有支持的视觉依据 | 正式入口确实由该 Agent 执行；保留必要父任务／session；导演可读取 |
| A05 | 导演完成分镜／图片／视频候选 | 实际模型输入、generation task、VideoVersion 和帧图可核验；提交中不算完成 |
| A06 | 装配 Agent 制作 Sequence、无声与旁白音乐版本 | 系统 Agent 调正式工具；render 可播放；素材和音频 provenance 齐全 |
| A07 | 合法的 Producer→编剧双节点链 | 真实任务按依赖顺序启动；编剧读取正确输入；Producer 不重复派发编剧 |
| A08 | 同一 Agent 两个节点实例、不同任务范围 | node、attempt、task、上下文各自独立；第二次只执行自己的范围 |
| A09 | 缺批准 Look、未选视频或 Sequence 输入不全 | 当前节点显示具体 gate／缺项；下游未启动；合法补齐后可继续 |
| A10 | Agent 声称完成但工具失败／产物缺失 | 节点不能成功；交接包无伪造 artifact；上游错误不被摘要隐藏 |
| A11 | 旧普通 Agent 聊天与旧 Producer 委派入口回归 | 既有正式制作仍可使用；没有被新 workflow 控制误伤 |
| A12 | 用户自建可运行的“装配＋审核”子流程 | 使用已有合法输入即可运行；不隐式重做编剧、资源、场景或导演 |

A03／A04 对尚未实现的一等资源类型诚实标注；不为测试把 Prop 或 Scene State 挤进角色字段并宣称体系完备。所有必需产物以当前仓库实际支持的契约安排。

## 6. Skill 绑定与人工审核测试 H

| ID | 动作 | 通过判定 |
| --- | --- | --- |
| H01 | 将一个正式 Skill 绑定给适用 Agent 后运行 | 实际加载路径、内容 hash／版本与快照一致；没有独立 Skill task |
| H02 | 绑定给不适用 Agent／冲突版本 | 后端拒绝或给出准确冲突，不只在前端标蓝线 |
| H03 | 运行中解绑／换版草稿 Skill | 当前 task 继续使用原快照；新 run 才使用新定义 |
| H04 | 正式目录内每个可用 Skill 的触发正例 | 系统 Agent 在实际适用任务中使用规则与正式工具；留决策和 receipt |
| H05 | 错误尾帧／无效桥接端点等不应触发的反例 | Agent 不强制接力或桥接；选择合法处理，不能因绑定就机械调用 |
| H06 | 一个审核的正常通过 | 精确对象和意见存档；下一 Agent 唯一启动；刷新可见已决状态 |
| H07 | 两个连续审核，先只通过第一轮 | 第二轮仍等待；下游 task 数仍为 0 |
| H08 | 第二轮通过，以及独立轮次的第二轮驳回 | 通过后唯一继续；驳回则停止，意见保留，无自动返工循环 |
| H09 | 重复点击同决策、并发相反决策、错误 request ID | 同决策幂等；仅一个有效决策；无覆盖、越权或误启动 |
| H10 | 待审对象被替换；无关项目字段另一次变更 | 必需对象变化使决策需复核；无关变化不让审核无故失效 |
| H11 | 普通流程审核与资源批准／视频 select／final 分别检查 | generic approve 不擅写正式指针；用户专用入口独立回执可核验 |
| H12 | Agent 内部人审、画布人审、服务重启 | 等待来源可区分；旧申请可恢复；前置 gate 不被画布许可绕过 |

H04 可用单独针对性夹具：正片没有必要桥接时，使用明确合格且需要过渡的测试端点；端点必须有合法来源。真实候选质量待观看，不能因为桥接接口成功就算视觉通过。

对 optional Skill 可做绑定／未绑定的对照，保持素材和任务目标一致，记录配置差异与决策。不能为了对照去掉 Agent 必需的基础 Skill 或核心工具。比较的是加载与可解释行为，单次画面优劣不足以证明因果。

自动化审核使用测试身份、测试项目、测试权限和标记。F2/F3 的正式 Look 批准、视频选片及最终定版仍是用户真实决策；若待决，材料可提交后继续其他独立故障测试，不伪造完成。

## 7. 故障、幂等、停止与恢复测试 R

这组是必需能力测试；对每个“未重复”判定，都检查 run／node attempts／正式任务／Provider 关联数量，而不是只看画布上一个卡片。

| ID | 注入／操作位置 | 通过判定 |
| --- | --- | --- |
| R01 | 连续双击运行，同幂等键并发启动 | 同一 run，预期每节点一次派发，无双份生成 |
| R02 | 同幂等键改变参数后重发 | 返回冲突，不能复用错误参数或另造任务 |
| R03 | 本地已建立派发意图但还未调用正式任务入口时重启 | 能识别未提交位置；只派发一次，或明确等待显式继续 |
| R04 | 正式任务已创建，但 workflow 本地关联写入前失败 | 由正式 request key／correlation 找回同任务；不能再创建第二份 |
| R05 | Provider 是否接受未知且无法查询找回 | `needs_reconciliation` 或等价状态；不重发、不下游；不宣称自动恢复成功 |
| R06 | 已拿到 video task ID，轮询中断／出现 5xx 或 429 | ID 和输入 basis 保留；按服务限制退避，查询收货原任务，没有新生成 |
| R07 | 已收货、节点成功与下游派发之间进程重启 | 已完成节点不重做；下游只有一次启动 |
| R08 | 人审等待、通过提交响应丢失、随后重启 | 同一申请／决策恢复；前一 Agent 不重做；下游唯一启动 |
| R09 | 重复／乱序／旧 attempt 的回调或事件 | 状态不倒退、不覆盖新 candidate／selected，不推动错误下游 |
| R10 | 浏览器刷新、关页、事件断线再打开 | 同一 run 可继续观察；不发起新 run，不误取消现有任务 |
| R11 | task 被既有 session governance 确认中断 | 如实标记中断；从合法检查点新 attempt 时明确记录，不冒充原 turn 续跑 |
| R12 | 制作中外部改变同一必需 canonical 输入 | OCC／freshness 阻塞或既有冲突行为；不能无声覆盖 |
| R13 | 人审等待时另一个合法任务使用其他资源 | 不被长时间持锁误阻塞；恢复后重新检查输入与取得必要锁 |
| R14 | 停止前无在途外部生成；停止后还有就绪节点 | 立即禁止下游派发，run／节点停止状态一致 |
| R15 | 停止时已提交视频，Provider 不支持取消，结果晚到 | 显示在途实况；保存关联；run 不改成功、不 select、不启动下游 |
| R16 | 两 worker 同领取一个节点，或多个同项目任务争资源 | 租约／CAS／现有锁保证不重复写入与派发；没有死锁或越过 ownership |

R03—R09 的关键窗口可用受控任务服务做确定性故障注入并重复两次；至少对 R06、R08、R10 做真实媒体／真实审核状态的演练。未知提交测试允许安全阻塞，它证明的是诚实性与不重复，不证明未知外部任务可自动找回。

针对不能自动恢复的 legacy task，交付范围声明必须写清：工作流状态可恢复、哪些任务可重新关联、哪些需新 attempt、哪些停在人工核对。不能用一个统一“恢复已支持”隐藏差别。

| ID | 用户可见操作 | 通过判定 |

| U01 | 页面打开，后端目录正常／不可用各一次 | 六员与真实 Skill 显示正确；不可用原因可见，不回落成假注册项 |
| U02 | 保存→体检→运行 | 显示真实保存版本与 run ID；首次任务状态来自后端 |
| U03 | 点击当前节点看输入、任务、产物 | task／receipt／素材与 node 对应；链接可打开真实项目资料 |

| U11 | 多标签页冲突、跨项目 run 事件、旧 run 事件 | 不串状态；冲突保留本地内容；当前画布只投影匹配的运行 |
| U12 | 关闭页面→重开→重新观察、继续或停止 | 从后端同一 run 恢复，不依赖 localStorage 中的运行状态 |

助手已知“按数量删除”和“清空已填内容”限制若未修复，报告中准确保留；不能在数量语句未完成时声称按精确数量成功。本阶段不用重新做整体前端审美评比。

## 9. 完整生产与新会话稳定性测试 E

### 9.1 第一轮：逐段真实贯通

在 F2 从正式页面启动：

1. Producer 只在限定范围内制定计划并交接；核对没有提前派发后续画布节点。
2. 编剧产出故事／故事段；检查项目事实和结束条件。
3. 资源 Agent 产出角色 Look 与职责内道具资料；提交可审材料，完成必要正式批准。
4. 场景 Agent 产出两个场景的现有事实和视觉依据；导演能读到正确版本。
5. 导演自主规划并完成真实分镜图／视频候选；选择方法前后记录实际输入与请求。
6. 对视频候选设两轮画布审核。第一轮通过后，第二轮仍等待；两轮意见各自保存。正式选片走原入口。
7. 装配 Agent 读取合法镜头版本，制作 Sequence、无声预览、旁白音乐可审版本。
8. 最后展示可播放 render、源镜头／音频引用及用户专用定版入口；没有用户动作时保持候选状态。

若默认实际输入契约要求调整顺序或将审批放在其他位置，在基线记录中写明理由；仍需证明六员各自真实制作和两轮独立审核。

### 9.2 最少六个 E2E 情景

| ID | 情景 | 通过条件 |
| --- | --- | --- |
| E01 | F2 六员新制作＋双审核＋可审音视频 | 六员 task／receipt／canonical／媒体贯通；无隐藏代做；必需 gate 状态真实 |
| E02 | F1 装配子流程，复用已批准素材 | 不重复制作上游；正式 Sequence／render 正确；复用与新制作不混算 |
| E03 | 双审核中第二轮驳回 | 前面合格产物保留；装配不启动；修复建议与意见可读 |
| E04 | 导演视频运行时断线／重启，随后再观察继续 | 原 task 找回并收货；无重复生成；装配只消费正确所选版本 |
| E05 | 冻结后 F3，新会话六员链 | 无逐镜答案指导，Agent 自选合法方法；运行与产物证据完整 |
| E06 | 用户修改合法顺序或重复一个 Agent 实例 | 合法范围确实按画布执行；不合法输入被准确阻塞，不偷偷替换为固定默认链 |

首次 E01 可分段调试，但最终需要一次经过正式启动入口的完整贯通，不能只把六个独立测试产物手工拼成总报告。

### 9.3 稳定性轮次

修复后冻结一份正式基线。在三个彼此独立的项目／会话中完成正常生产链，**至少一个为 F3 未见新故事**；可以保留经合法批准的基础测试素材，但每轮新产物和复用素材要区分。先前调试轮不能充当冻结后的通过次数。

三个轮次均需运行机制通过，无重复派发、越审、丢任务、错误版本交接和伪成功。媒体可有需用户挑选的候选，不要求随机模型第一次就出片完美；必须留下候选筛选、缺陷诊断和用户反馈。三轮只是本阶段工程验收规模，不是对长期可靠性或视觉泛化的统计保证。

如果真实用户审批尚待回复，保持 `WAITING_USER`，先做全部不依赖它的确定性与故障测试。待用户操作后再完成相应生产轮次。不得用伪批准把三轮凑满。

## 10. 视频、声音与成片的具体检查

### 10.1 逐镜检查

每个重要视频至少查看第 0 帧、过程中的关键动作帧、最后一秒和真实提取尾帧。与相应批准 Look、道具、场景和镜头目标对照。

| 维度 | 检查点 |
| --- | --- |
| 身份／Look | 狐狸毛色与脸部特征、背心、形体是否在近景／远景交替后漂移 |
| 道具 | 铜邮筒形态、信件持有／交出关系；无凭空复制或消失 |
| 空间 | 街角与钟楼可区分；位置、方向、出入路径符合剧情 |
| 动作 | 取信、携带、递交、确认完成可理解，不只是相似静态画面 |
| 终态 | 信已交到收信人，未因随机结尾静默改写故事 |
| 参考语义 | 实际首帧／尾帧／reference 模式与记录一致；不把 reference 第一槽冒充硬首帧 |
| 接缝 | 正常切镜保留；确有断裂时先看端点有效性再修，不为相似度强行桥接 |
| 版本 | 正片用的是用户选版；新候选未被选用时不覆盖已正式选择 |

本阶段不要求重测所有视频方法，也不强制迁移 Grok。使用本轮真实配置的合法路径即可。若是视频模型质量问题，形成可复现缺陷；若是接线／版本／Skill加载导致，必须在本阶段修复。

### 10.2 成片检查

检查 Sequence 镜头顺序与 selected 指针一致；文件可解码、时间轴无意外空段／重复镜头、音视频时长与媒体流正确。可用现有 ffprobe／播放器核验，不能以文件大小替代播放。

旁白内容与剧情一致，句子不被切断，关键动作可听清。音乐按实际配置连续或按场景切换，转场不过分突兀，不压住旁白；原声保留／静默与用户或本项目计划一致，避免重复音乐与旁白。一次观感不佳可以迭代候选，所有版本保留 provenance。

给用户交付逐镜候选、首中尾帧索引、无声与带音可审版本、推荐理由和已知问题。请求成功、软件通过、视觉推荐和用户选片四种结论分别写。

## 11. “流畅运行”的量化观察

以下为开发环境的体验目标，最终报告填写实测值，不虚构服务 SLA；图规模以首版单链约十个节点为主。

| 项目 | 目标与核验方法 |
| --- | --- |
| 启动响应 | 完成合法校验和持久化 run 后尽快返回，不等模型完成；开发环境通常应在约 2 秒内，异常说明实际瓶颈 |
| 状态可见 | 推送正常时数秒内投影；轮询正常时约 5 秒内看见；记录后端事件到页面可见的延迟 |
| 人审继续 | 决策成功后页面明确已处理／排队，不停留在可重复批准；仅派发一次下游 |
| 刷新恢复 | 页面从后端找回同一 run 和当前对象，不要求用户重搭草稿 |
| 长任务等待 | 展示真实阶段／task 与等待原因；页面可操作，不把 Provider 慢当程序卡死 |
| 断线 | 明确观察连接异常；重新连接／快照校准后与后端一致 |
| 停止 | 立即禁止下一节点并可见停止请求；外部取消按实际能力报告 |

分开统计：UI／API 延迟、队列等待、文本思考时间、图片／视频／TTS 时间、人审时间和恢复时间。不要为了降低表面延迟关闭思考，也不要把人工等待计入服务处理时长。

## 12. zcode 的发现问题与修复流程

### 12.1 每个缺陷采用同一最短记录

```text
bug_id:
baseline_commit / config_hash:
case_id / fixture / trial:
expected:
actual:
run_id / node_id / attempt_id / task_id:
first_divergence_event:
source_layer:
evidence_refs:
root_cause:
minimal_fix:
affected_cases:
verification_after_fix:
remaining_user_decision:
```

先定位“第一处偏离”，再追后续连锁现象。例如装配缺视频，可能根因是上游选片 gate 未完成，不应立刻把装配 prompt 写得更长。

### 12.2 修复顺序

1. 先修伪成功、重复派发、越过审核、丢 task ID、错误项目／版本写入与思考参数丢失。
2. 再修输入契约、Skill实际加载、任务范围、过期对象与恢复入口。
3. 再修页面状态错误、按钮状态和断线恢复。
4. 最后针对已排除接线问题的 Agent 决策与媒体缺陷做候选实验或最小 Skill 修订。

修复前保留失败证据，修复后跑原用例与受影响小链。关键缺陷修复后，重新冻结并用新会话复验整链；不能以最终一次成功掩盖基线混用。

### 12.3 需要用户决定时

只有审美、剧情变化、正式批准／选片／final 等真实决策依赖用户。提供具体可审对象和方案，不只发“需确认”。其余已授权的代码、接口、修复、测试与独立故障演练继续完成，不停在泛泛建议。

## 13. 验收门槛与交付格式

### 13.1 接入可用的硬门槛

- 六员均有真实入口适配、至少一次各自产出职责内新产物的证据；目录与实际入口对应。
- 合法单链和用户可修改的合法实例按图执行；不支持图形被明确挡住。
- 真实数据交接可追溯，canonical／ownership／OCC／locks／receipts／truth gates 没有旁路。
- 全部真实文本测试请求已请求开启思考，覆盖率 100%；不静默换模型或关闭思考。
- Skill只绑定，当前正式适用 Skill具有加载与触发正例、禁用／不应触发反例。
- 双审核、通过继续、驳回停止、对象版本检查与幂等决策均通过。
- 启动、派发、收货、继续、停止没有无法解释的重复或错版；已知 task 可恢复关联，未知提交安全阻塞。
- 真实页面能完成操作和观察；刷新、断线和隔离重启后状态一致。
- 受影响回归无未解释关键失败；冻结后的三个独立正常生产轮次按约定取证。

### 13.2 无条件阻塞接入验收的情况

隐藏脚本代做生产、用 Producer 子任务与画布重复执行、批准旧版本继续新对象、思考参数丢失后仍报通过、错误项目／权限写入、没有 receipt 的伪成功、提交不明直接重发、浏览器是唯一运行状态来源。

视觉瑕疵与软件接入应分别判定。软件可接入但画面待优化时准确写出范围；若视觉问题根因是错误参考输入、错误 Skill 或旧版本消费，则仍是接入阻塞，不能归为“模型随机性”免修。

### 13.3 最终报告结构

```markdown
# 本阶段工作流接入与测试报告
## 基线与范围
## 六员真实入口与产物对应
## 契约 / API / 状态 / 审核 / 恢复实现
## 文本模型思考模式核验
## 测试总表（M/C/A/H/R/U/E）与全部轮次
## 缺陷、根因、修复提交与定向回归
## 冻结后新会话生产与稳定性结果
## 视频、声音、成片与用户决策状态

```

按“测试情景”“断言条目”“真实模型调用”“生产项目轮次”分别统计，不能把一次请求中的多个断言包装成多个独立真实项目。清单共 76 个 M/C/A/H/R/U 情景，另有 6 个 E2E 情景，合计 82 个情景；这是覆盖计划，不能预填 passed 数字。

交付页面路径、可用示例工作流、贯通 run 索引、逐镜和成片观看材料、测试报告、commit 链和剩余用户待决清单。正式用户尚未定版时，用“可审候选已交付／等待选片”描述，不写“用户最终验收通过”。

## 可直接执行的任务书

你现在负责 Phase 44A，目标是在不改动已获用户认可镜头的前提下，完成《雨灯归航》的正式选片收口，并为后续成片 Agent 与独立视频 Skill 盲测提供**同一份可验证的冻结输入**。这是两个下游任务的共享前置批次，不要顺手启动盲测或重构后期。

### A0. 只读核验和差异表

1. 查真实子仓/父仓 HEAD、工作树、正式 Skill 版本、registry、模型配置、批准资源、Project/Shot/VideoVersion canonical、用户评审文件、生成回执与媒体。报告写 `6722bd0`、v1.3.0 等仅作查找线索。
2. 逐镜列出：顺序、候选版本、用户最后裁定、当前 final 指针、视频时长、源 URL/受管媒体、真实首尾帧、后续依赖、是否有原生音轨。另列 12 个相邻剪辑点的“剧情/动作/空间”风险；相邻帧像素不相似不能单独判失败。
3. 把“已锁定”“待回拨”“待重做”“待用户终审”四种状态分开。时间靠后的自动 final 不覆盖用户已表达的选择。此前单文件反馈被换轮重置过，需保留分轮档和逐字证据。
4. 验证报告提到的 `_43_set_final.py`、`_43_extract_end_frames.py`、评审页工具是否仍适用；不要盲运行脚本或假设路径有效。

### A1. 两笔正式回拨

在业务层按用户最新裁定处理报告中两笔：`s01_c04 → vv_80dc90a5`、`s02_c02 → vv_4bdf6b08`。先核对版本 ID、用户评论和可用媒体；若实际记录有更新，以更新的明确用户裁定为准并解释差异。set-final 后按系统正式流程更新/重新提取末帧，检查下游依赖 freshness、OCC/revision、指针与媒体，不以“数据库字段改了”作为完成。保留被撤下版本供回看。

### A2. `s02_c03` 最小迭代

用户此前指出门的视觉修好了，但人物没有开门。请先检查原视频的动作、尾态、场景和上一镜端点，提出一个最小生产方案：继续使用已证明有用的场景锚定和门的规格约束，同时明确人物伸手、触门、拉开门、跨向门后的可拍动作及镜头容量。避免约束把动作本身排除。通过正式 Agent/生成入口制作有限候选，保存选择前理由、真实编译请求、任务回执、首中尾帧与失败样本。给用户并排可看素材；用户未终审前标候选，不把自动前移的 final 当批准。若第一次仍失效，先归因，再决定是否第二次迭代，不无界生成。

### A3. 形成两种快照

- **制作快照**：若 `s02_c03` 仍待用户看片，可先冻结其余 12 镜，并用明确标记的临时候选做成片管线开发；该版本只可用于工程预览，不能叫最终成片。
- **正式快照**：13 镜均有用户裁定、final 与裁定一致，末帧及依赖已经核对后生成。冻结 commit/Skill/模型配置、批准的 Look/道具/SIV、每镜版本 ID、媒体文件及内容哈希、视频/音频流规格、时长、顺序。某些旧版本只有 provider URL 时，先下载到受管媒体并计算哈希；URL 过期或取不到时阻断正式快照，不能用磁盘同名文件顶替。

同时生成只读 `assembly_input_manifest` 草案，字段至少包括 `project_id`、`snapshot_id`、`shot_id`、`order`、`video_version_id`、`approved_status`、`media_uri`、`sha256`、`duration_probe`、`has_audio`、`source_receipt_ref`、`revision`。字段是契约建议，具体复用仓库 schema。若成片 Agent 接入时 manifest 与 canonical 不一致，拒绝导出并报告差异。

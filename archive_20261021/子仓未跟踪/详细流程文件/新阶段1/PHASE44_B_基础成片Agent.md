# Phase 44B｜基础成片 Agent、时间线与无声导出

可整段交 zcode。前置：Phase 44A 至少已提供有版本与哈希的**制作快照**。本批可以用待裁定镜头的临时候选验证工程管线，但预览需明显标记；只有正式快照可作为交付成片输入。

## 可直接执行的任务书

你现在要建立第一版后期/成片能力。用户目标是“将几个视频连在一起，适当加入旁白和音乐”。本批负责基础 Agent 和可复现的画面时间线；下一批负责真实声音接线。先审计仓库中已有的 Agent 注册、权限、tool schema、作业队列、Project/Shot canonical、媒体托管、导出工具及后期概念，能复用就复用。不要复制一个与原 canonical 平行的新项目真相。

### B0. 写设计决策记录，再编码

给出两到三种轻量方案及选型理由：纯脚本拼接、在现有 Director 里增加导出命令、独立 Assembly Agent + 确定性时间线工具。预期第三种较合适，但以真实仓库边界为准。分别说明：谁选择镜头顺序与剪辑节奏，谁能修改什么 canonical 字段，渲染任务如何创建、恢复、重试，媒体存在哪里，哪些环节要用户终审。不要把“Agent 自主”实现成一次提示词输出 FFmpeg shell 命令后直接执行。

### B1. 成片输入与最小时间线契约

从 A 的冻结快照读取镜头，**先默认按 canonical 叙事顺序全部保留、整镜使用、硬切**；如剧情明确需要裁去生成时多余的开头/结尾，Agent 可提出 `in/out` 微调，但要列依据、可预览并记录原镜头与截取范围。跨组切点单独标记。别机械地给每处加溶解或桥接，尤其有动作连续性、镜头语言或时空跳转时。

时间线草案至少记录：

```json
{
  "project_id": "...",
  "snapshot_id": "...",
  "assembly_revision": 1,
  "shot_items": [
    {"shot_id":"s01_c01","video_version_id":"...","media_sha256":"...","source_in_ms":0,"source_out_ms":5000,"timeline_start_ms":0,"transition":"cut"}
  ],
  "narration_cues": [],
  "music_bed": null,
  "render_profile": {"container":"mp4","video_codec":"h264","audio_codec":"aac"}
}
```

这仅是示例，不强迫另建同名 schema。最小不变式：每个 `source_out > source_in` 且不超源时长；排序、时长及转场都能计算成确定时间线；镜头版本、哈希、快照 revision 完全匹配；任何媒体丢失/不可解码/权限不足都应给出可定位错误，不偷换素材。

### B2. Agent 与工具边界

Assembly Agent 的工具应让它能“读取批准的项目结构和媒体元数据 → 形成剪辑草案及理由 → 检查规则/依赖 → 发起预览渲染 → 观察导出诊断 → 修订草案 → 提交用户评审”。它不得调用视频生成去修镜头；发现坏镜头要返回 `shot_id`、症状、来源时间戳，交视频制作线处理。它只写新的 Assembly/Render 版本，不直接修改 Story、Look、SIV 或 Shot `final_video`。采用仓库已有 OCC、revision、receipt、resource lock 和任务恢复机制；不中断用户正在使用的 Director。

将“镜头排序、留白、转场建议、旁白候选”作为可审阅提案；将输入解析、时长、格式转换、音视频时间戳、编码、文件校验作为确定性工具。Agent 报告任何“已渲染成功”必须附真实任务回执、输出路径/哈希和媒体探测；不能只附语言总结。

### B3. 画面渲染实现

使用 ffprobe 检查每条视频的尺寸、帧率、像素格式、编码器、time base、rotation、音轨、开始时间与实际时长。若流完全兼容可试 concat demuxer；条件不满足先规范化素材、重置 PTS，再作拼接并明确编码配置。不要对异构 mp4 强制 `-c copy` 后只凭进程退出码认定无黑帧、卡帧或音画同步成功。固定导出 profile，由仓库现有标准决定分辨率/帧率；不放大到比素材实际信息更多。短切点检查黑帧、重复/缺帧、PTS 单调性和时长误差；保留原画面比例，必要时用一致的填充策略并在报告说明。

原镜头如带音轨，先探测并记录。第一版可提供“关闭原音轨/保留可用原生环境声”两种显式策略；切忌每镜的原生背景音乐与未来统一 BGM 叠加。B 批次的无声画面成片仍应有正确总时长与可播放视频流，音轨策略留在 manifest。

### B4. 以真数据验收

1. 小样本：取 3 个真实镜头，覆盖同组动作连续和跨组切换；预览开头、中点、两处切点及尾帧。记录版次和渲染耗时、无视频生成费用。
2. 全片工程预览：依据制作快照尝试 13 镜或实际核验后的数量，输出时间线表、片长、镜头起止、每镜来源版本、可直接观看的 mp4 和接缝清单。临时镜头不能伪装成已批准成片。
3. 修改测试：替换一镜的**已批准**版本，只生成新 AssemblyVersion/RenderVersion；旧输出、旧 manifest、旧媒体哈希仍可找回。无需重生成其他镜头。
4. 中断测试：渲染进程重启后能按 job receipt 找回已完成/失败状态；不重复覆盖旧输出。不接受一个孤儿本地 mp4 作为完成凭证。
5. 实际调用一次正式 Agent 会话，保存加载上下文、选择理由、工具轨迹、导出回执和用户可评审预览。硬编码脚本成功只能算工具验证，不算 Agent 验收。

### B5. 交付

提交 `PHASE44_B_REPORT.md`，含代码 diff、所有新增/复用入口、时间线 schema 与实例、Agent trace、3 镜和全片预览、媒体探测、测试结果、已知限制、供 C 批次使用的音轨与 cue 时间契约。至少有一个**完全不依赖 TTS 服务**的可播放成片；若旧片正式快照还缺用户终审，明确标注“工程预览”，继续让 C 批次用测试 cue 接线。

本批不做复杂转场库、自动配乐生成、镜头内对白对嘴、自动字幕版式或自由拖拽 UI。这些功能只有用户看过第一版作品、提出具体缺口后再排。

# Phase49：候选 Agnes Skill 接入与可剪辑分镜测试执行书

交付对象：Zcode。日期：2026-10-07。

本文件是下一轮执行要求，不是已完成的仓库修改或生产验收。当前已审阅本轮候选 Skill、首帧策略、视频动作与因果策略、跨镜头衔接策略、失败诊断与修复策略、模型契约速查及研究自查。正式仓库、两个 v1.4.0 Skill 原文和 PHASE48 原始报告须在执行环境读取；不得把文件名、历史摘要或候选作者的转述当作已读取原文。

## 1. 本轮目标与用户已确定的方向

本轮集中改善 Skill 的制作决策和实际出片流程。保留现有六个 Agent、工作流和治理底座，不重建系统，不扩展工作流组件种类。

- 免费模型进入可测试范围；使用用户已有 Token Plan。模型探针和参数核对作为接入检查，不让配额文档型号未同步成为长时间阻塞制作的研究任务。
- 所有新生成的分镜视频素材至少 8 秒；默认 10 秒，根据动作与留量需要选 8–12 秒。不要通过生成更短视频再循环、插静帧或放慢来凑时长。
- 生成素材时长与成片保留时长分开。成片中的一个镜头可以短于 8 秒；用户需要的是有剪辑余量的源素材。
- 主动作仍保持清晰、单一、有因果。较长时长用于准备、执行、结果和剪辑余量，不用于塞入更多剧情任务。
- 初期无旁白、无主动配音；保留合格原生环境声和音效。人物对白另设专项。
- 用户暂缓大量首帧候选供选的路线，本轮不把批量抽图作为主要改善方法。
- 全部适用的文本 Agent 和视觉审查调用开启 Thinking，核对真实出站字段。图像和视频请求不要混入文本思考字段。

官方 Flash 文档当前支持视频时长 4–12 秒，因此本轮的 8 秒下限是用户制作政策，不是模型接口下限。默认 10 秒是本轮起始方案，尚无证据证明其优于其他时长。

## 2. 对候选包的审查结论

### 2.1 保留的内容

候选包的有效骨架包括：规划与最终提示词分开；首帧只写可见关键信息；按实际需求选择最小参考；动作先规划起态、步骤、接触、结果、视角；区分动作连续、空间连续、身份保持和正常切镜；按最早偏差定位根因；候选不静默替换正式选版；自动审查辅助用户判断。

这些规则值得进入真实测试，但文档完整不等于制作效果已经通过。尤其不能把候选作者转述的观察升级为新的受控实验结论。

### 2.2 接入前要做的内容修订

| 位置 | 当前问题 | 本轮要求 |
| --- | --- | --- |
| video-action-causality 的动作容量与时长 | 用 4–6 秒描述单主动作，且把全镜统一变长写成失败出口 | 保留官方能力范围，生产政策改为至少 8 秒、默认 10 秒。失败判据应是拖沓、动作过载或缺少有效片段，而不是统一时长本身 |
| first-frame-image 的质感基线 | 短提示词纯文生图质感最好来自特定历史观察 | 改为待复验基线；不得声称对所有题目或模型最优。身份与质感都要达到作品要求 |
| first-frame-image 的参考路径 | “质感可让渡”容易被用来降低用户标准 | 参考承担身份约束；若质感掉到用户不可接受范围，仍应判失败，而不是以一致性改善抵消 |
| 提示词删减规则 | 绝对禁止重复静态信息可能删掉动作所需约束 | 删除冗余，但保留关键的持有者、接触对象、动作方向和必须持续保持的关系；以不冲突且足够明确为准 |
| shot-continuity 的空间连续 | 同一空间换机位可能被直接送入原尾帧起步 | 同机位动作延续可用合格尾帧起步；新机位需重建构图并核对空间、轴线和人物位置。尾帧可作为状态依据，但不能替代新机位设计 |
| shot-continuity 的状态相等 | 容易把正常换场也要求成上一镜物理尾态相等 | 相等规则用于确实延续的动作和状态；时间跳跃、换场按剧本允许的状态变化核对 |
| 缺少上游媒体的处理 | 可能为了继续执行，擅自改成正常切镜 | 先读取合法上游事实；明确动作连续任务若缺少必要状态证据，应报告缺项，不能猜测或悄悄改变叙事要求 |
| repair-diagnosis 的小偏离 | 按发型、配色等类别固定判断严重程度 | 同时评估范围和重要性；识别性发型、关键道具主色、人物身份即使局部出错也可能是重大偏差 |
| 修复顺序 | 主要考虑重试、根帧和重建 | 增加“审查完整素材 → 判断能否裁切保留 → 能保留则给剪辑建议 → 不能保留再修根因” |
| 跨镜接力端点 | 默认上一源视频的物理最后一帧 | 增加有效区间与剪辑端点；下一镜依据实际保留片段的最后一张保留帧和该处状态决策 |
| 免费模型路径 | 标准版视频参考与 Flash 路径混在方法菜单 | 免费主链只调用实际免费的模型与其能力；标准版视频参考作为能力备选，不列为本轮必须完成的主路径 |

不要把“禁止重复静态描述”改成又堆满所有角色小传的长提示词。目标是删冗余、保关键关系，而不是机械追求字数最少。

## 3. 时长与剪辑留量政策

### 3.1 素材时长

| 镜头情况 | 起始生成时长建议 | 规划重点 |
| --- | --- | --- |
| 简单反应、观察、轻微动作 | 8 秒 | 起态清楚，动作后有可读结果 |
| 常规单主动作、普通叙事镜头 | 10 秒 | 准备 → 执行 → 结果，保留剪辑余量 |
| 关键接触、道具交接、需要较完整起止阶段 | 10–12 秒 | 接触与持有者变化完整可见，避免同时复杂运镜 |

复杂动作在 12 秒内仍不清楚时应合理拆镜；拆出的每条新视频素材仍遵守至少 8 秒。不得把“更长”当作单镜动作容量已扩大的证据。

这里的秒数是请求素材总长度，不是对模型内部动作发生时间的精确承诺。提示词用动作阶段表达顺序，不把关键接触安排成只能发生在最后瞬间。

本轮不得使用接口默认时长；实际请求、任务回执和下载文件时长都要检查。文件真实时长异常时记录异常，不仅检查请求里的 seconds。

### 3.2 每镜规划需要表达的内容

在已有分镜或任务结构中找到对应字段；以下为语义要求，不是新建 schema 的授权：

- 剧情任务：观众必须理解的一个核心动作或变化。
- 起始状态：人物数量、位置、姿态、道具持有者及接触关系。
- 主动作步骤：因果顺序和必须可见的关键事件。
- 必须保留的内容：关键接触、交接、身份亮相和结果状态。
- 结束状态：为下一镜或剧情理解提供什么事实。
- 生成素材时长：至少 8 秒，并说明为何选择该长度。
- 剪辑余量：可删减的准备、停顿和结果停留；不能删掉的过程。
- 衔接要求：动作延续、空间延续、身份保持或正常切镜。

不要把剪辑余量写成必须静止的填充时间。准备动作、视线、环境运动和结果停留应自然，并服务于当前镜头。

### 3.3 错误是否可剪的判定

| 观察 | 处置 |
| --- | --- |
| 瑕疵只在开头或结尾，存在完整、连续、足够可读的主动作与结果 | 提出裁切区间，保留源素材；核对剪后叙事与声音 |
| 中间有瑕疵，但前部或后部本身已完整表达当前剧情任务 | 可以选择完整合格区间；不能只因瑕疵在中间就一律重做 |
| 错误发生在必须保留的交接、接触、身份或因果节点 | 不允许删掉关键过程后宣称合格；修复或重新规划 |
| 主动作和结果分落在错误区间两侧，直接拼接会跳步 | 不作为单镜裁切成功；若改成多镜表达，须单独验证叙事和空间关系 |
| 整段身份、人数、关键道具或动作因果错误 | 回到对应根因层修复，延长素材不能挽救 |
| 画面能保留，但裁切造成关键音效脱离动作或留下半句人声 | 音频需复核；不能只以画面合格放行 |

示例：生成 10 秒素材，实际选取源片第 3–8 秒，成片保留 5 秒。这满足素材至少 8 秒的政策，但只有在关键动作与结果均完整、无重大错误且节奏可接受时，才是可用镜头。

较长素材的收益是假设为“更容易找到完整合格区间”。本轮必须用真实片段验证；如果多出的长度只增加错误或拖沓，就应调整阶段安排或方法，而不是继续拉长。

## 4. 生产流程与职责

### 4.1 工作顺序

1. Producer 读取作品目标与现有项目事实，按实际工作流委派。
2. 编剧确定剧情因果；资源与场景 Agent 提供既有权限范围内的身份、Look、道具和空间事实。
3. 导演规划各镜起态、核心动作、结果、衔接与至少 8 秒的素材时长。
4. 导演按需加载候选制作 Skill，选择首帧与视频模式；首帧合格后才进入依赖该首帧的视频生成。
5. 生成后完整审片，标记错误、关键事件和可保留区间；已有视觉审查辅助筛查，不新增正式 Agent。
6. 能裁切保留就交付具体剪辑建议；无法保留则由制作责任方定位并修复。新结果始终保留候选身份。
7. 存在动作接力依赖时，先确定实际保留区间与离开状态，再规划依赖该端点的下一镜。
8. 装配按已有工具和正式选用关系完成裁切、排列、原生音效处理与成片预览；最终由用户观看与选用。

准确注册 ID、工具权限、谁能写选版以及谁能执行裁切，必须以仓库为准。导演负责生成决策；装配发现问题应反馈给相应制作方，不因绑定了此 Skill 就取得修改其他 Agent canonical 的权限。

保留既有人工审核位置和正式选片机制，不为本轮添加每镜必经的额外人工审批。若允许自动预筛有效区间，可以在原有授权范围内给出候选建议；依赖链必须绑定明确版本，用户换版后按真实依赖复核。

### 4.2 剪辑端点和尾帧接力

必须区分：源素材物理尾帧、候选剪辑区间的最后保留帧、用户实际选用区间的最后保留帧。

- 如果源素材后部被裁掉，动作接力依据保留片段的真实离开状态；不能继续取源素材末尾。
- 抽帧要来自最后一张实际保留的视频帧，不是抽取 trim_out 之后第一张被排除的帧。
- 源素材版本、有效区间、抽帧时间或帧号、下一镜依赖关系需要可追溯。
- 裁切变化影响已依赖原端点生成的下一镜时，先复核该依赖；不自动判其必然失效，也不假装依赖没有改变。
- 正常换场、独立首帧等未依赖该尾帧的镜头，不因前镜裁切而机械重做。
- 用户自己后期剪辑时，也要交付接力所依据的端点和建议保留区间；若用户另选端点，再检查受影响镜头。

优先复用现有 Sequence、片段入出点和媒体版本机制。若现有装配尚不能表达裁切，就先输出可手动执行的建议区间并验证预览；新增工具或持久字段的最小改动另列说明，不冒称 Skill 文字已赋予接口能力。

## 6. B 批：规则情景检查

先用合法项目事实或隔离夹具检查以下情况。情景检查只验证决策、字段和依赖，不证明真实画面质量。

| T24 | 新会话只给作品目标和项目事实 | Agent 自行选方法，执行侧不提前给逐镜答案 |

夹具不得绕过既有 Binding 检查；因缺 Look 或 SceneInstance 被拒，只证明当前夹具缺事实，不能据此判 Provider 不支持。

同方法重试次数按“首次生成与追加重试分别记录”解释；如果采用候选里的两次追加重试上限，记录总尝试而不混淆。因网络或排队失败的技术重试与已完成但画面不合格的重生分开统计。

## 7. C 批：旧 Skill 与候选 Skill 的真实制作对照

### C1：对照约束

两组使用相同作品任务、同一实际免费模型、同一素材时长、同一画幅和同一合法资源事实。常规视频对照先统一 10 秒，避免把时长变化混算成 Skill 改善。

旧组使用读取并冻结的正式制作 Skill，候选组使用修订后的候选规则；双方都明确接收至少 8 秒的任务要求。旧组不得以过去更短的历史成片冒充同条件对照。

策略可以自主选择参考数量、提示词和模式；这些正是被测试的制作决策。若要单独定位某项策略的收益，再固定其余因素做局部对照，例如同一合格首帧比较动作规划，不把“所有模式固定”写成妨碍策略选择的条件。

保留所有首次尝试和失败样本。候选/返工允许量一致；若单边技术故障或资源缺失造成不等条件，单列而不硬算输赢。不得只展示反复重试后最漂亮的一条。

### C2：真实题目覆盖

| 探针 | 要覆盖的制作问题 | 主要看什么 |
| --- | --- | --- |
| P01 | 单主体写实首帧质感 | 短提示词基线与旧方法的画面质感、光线、材质和构图 |
| P02 | 同一角色多镜身份保持 | 必要参考是否兼顾身份与质感，不能用省参考逃避硬要求 |
| P03 | 双人道具交接 | 人数、站位、接触和持有者转移是否完整可见 |
| P04 | 写实手部物件操作 | 主动作流程不跳步，物体接触与结果清楚 |
| P05 | 同一动作跨镜继续 | 根据合格有效端点选择方法，动作方向与状态衔接 |
| P06 | 同一空间换机位 | 机位合理变化，人物、道具和空间关系保持 |
| P07 | 正常电影切镜 | 不强行接力或插桥，身份与故事关系仍清楚 |

题目细节由编剧和导演在测试环境自主设计，覆盖这些难点即可；不向受测 Agent 指定哪一镜必须使用某模式。评价者可持有上表作为验收标准。

P01 可先做图片对照；涉及视频的探针均使用至少 8 秒源素材。首帧不合格要记录为首帧失败，不偷偷换掉再报告视频首尝成功。

### C3：审片与记录

先完整播放每条素材，再根据关键动作、接触点和疑似错误位置补查帧。首中尾抽样不能替代完整审片。

每条结果记录：题目与镜头 ID、组别、Skill 版本、实际模型与模式、提示词、参考资产职责、素材真实时长、首次或返工、源媒体版本、错误时间区间、必须保留事件、建议剪辑区间及结果状态。

分别评价以下项目，不用平均分掩盖硬错误：

- 工作流运行、真实请求与产物是否完成。
- Skill 是否实际加载，关键决策是否符合规则。
- 首帧与原片画面质感、人物自然性。
- 身份、人数、道具和空间事实。
- 动作因果及关键接触过程。
- 存在何种完整、连续、可读的合格区间。
- 剪后可用片段与相邻镜头是否衔接。
- 原生音效是否合格，裁切后是否同步。
- 用户是否接受该画面和片段。

至少区分“原片整体合格”“原片有错但能裁切得到合格片段”“裁切仍不能完成剧情任务”。即使剪后可用，也保留原片错误记录，不把它重新命名成原片全段成功。

最终同时报告首次可用情况、同条件返工后的最好结果、修复代价与用户观看反馈。自动审查不是最终审美裁决。

### C4：时长探针

如果常规对照显示素材留量确实影响可用片段，再选代表性题目，在固定 Skill、模型和任务条件下比较 8、10、12 秒。此处只改变时长，避免同时换参考策略或模型。

检查更长素材是否增加完整合格区间、关键事件是否仍清楚、末段是否出错、剪后节奏是否好。不要从“生成成功”推出“容错率提高”。若主动作过载，调整规划或拆镜，而不是一律选择最长。

## 8. D 批：新会话完整故事与修复闭环

### D1：自主制作

新建隔离测试项目，或按仓库已有方式隔离候选运行。输入只给作品目标、候选 Skill、合法资源和项目事实；不提前给逐镜方法答案。

完整故事要包含目标、阻碍、动作带来的状态变化和可理解的结果。镜头数由剧情决定，不设置每组固定镜数，不通过延长停留冒充剧情丰富。

Agent 自主完成规划、资源读取、首帧、视频、审查、可用区间建议和装配预览。每条新视频源素材至少 8 秒；用户可以自行后期剪辑，因此交付全部源素材、区间建议和必要依赖说明。

### D2：真实修复

优先使用实际产生的失败镜头验证修复，不为凑失败数量主动污染正式素材。没有出现某类失败，就如实报告该修复路径未获得真实验证；B 批的规则情景不能替代。

修复顺序：完整审片 → 确认偏差时间与重要性 → 判断能否保留完整剧情区间 → 必要时定位最早根因 → 改方法或重做相应素材 → 比对是否修掉原问题以及是否引入新问题 → 保持候选身份 → 按既有用户选版机制进入正式链。

尾部有错误但提前已有合格结果时，优先保留合格区间；交接瞬间错、关键结果缺失或全段身份错时，修根因。局部错误不等于有局部编辑接口；Agnes 图像重绘后的合格部分必须重新核对。

正式换版或裁切端点变化后，按实际依赖复核下游；既不能忽略依赖，也不能把全片重做设为默认。

### D3：停止与发布

- 技术链失败：定位传参、任务或素材可访问性问题，修复后重测对应环节。
- Skill 决策失败：修规则后重测受影响情景与代表性真实镜头，不重复无关整套测试。
- 方法重复失败：遵守预先冻结的有限重试和换方法规则，明确记录未达标。
- 用户仍不满意：报告当前方法未达画质目标，不能用系统通过或相对改善抵消；可说明更换模型是下一步备选。
- 本轮没有通过用户观看：候选继续保留，不声称已正式提升制作质量。

是否替换、扩展或保留独立 Skill，依据真实仓库冲突和本轮结果决定。不要求必须把新包升级成正式版；失败也是有效结果，但需要解释失败出现在制作决策、模型结果还是底座接入。

## 9. 每批交付与最终报告

每批完成后按依赖继续；不是只执行 A 批。保留既有人工看片和选版关口，在关口提供具体媒体、建议区间和需要用户判断的事项。

每批至少交付：修改与未修改范围、实际运行入口、冻结的 Skill/模型版本、真实任务和媒体证据、结果与失败原因、下一批前置状态。

最终报告按以下顺序回答：

1. 新 Skill 是否实际加载，Agent 是否自主做出合理制作决策。
2. 素材至少 8 秒的政策是否落实，默认 10 秒是否值得继续保留。
3. 新旧同条件对照中，原片和剪后可用片段分别有哪些改善或退步。
4. 哪些错误可以裁切保留，哪些关键因果错误仍需重做。
5. 实际保留端点与下一镜依赖是否一致，是否出现源尾帧与剪后尾态混用。
6. 用户画质要求是否达到；未达到的部分具体是什么。
7. 是否建议正式采用、继续候选迭代或转向更强模型，依据哪些真实结果。

验收表初始全部标“待执行”；只依据真实证据改状态。不要把本文件、本轮本地规则模拟或候选作者的自查当作仓库测试通过。

请完整执行附件《PHASE49_AGNES_SKILL_INTEGRATION_AND_EDITABLE_SHOT_TEST.md》的 A–D 全部批次，并读取同附的候选 Skill 与参考文件。先核对真实仓库里的两个正式 Skill、加载机制、六个 Agent 权限和裁切/选版/依赖机制，再按执行书修订并接入独立候选，不静默覆盖正式版。

每批交付真实修改、请求/任务证据、可播放媒体、建议剪辑区间与失败分析；满足前置条件继续下一批，遇既有人工选片关口再给具体候选。最终分别报告系统运行、Skill 遵循、原片质量、剪后可用性与用户验收，不把生成成功等同于画质合格。

# Phase48 E：多风格、完整剧情与正式 Skill 验收

先读 [总控计划](PHASE48_00_REVIEW_RESEARCH_AND_BATCH_PLAN.md) 和 A—D 交接。本批将有效方法放进完整作品，并判断哪些规则可以进入正式 Skill。前批失败的能力应先修复或明确排除，不把失败能力隐藏在“全流程完成”中。

## 作品规划

测试三种不同风格：清晰二维动画、水彩绘本、电影感写实。每种先固定风格依据，避免作品内途径变化被误判为模型能力。必要时按真实模型能力调整，但写明调整与不可执行项。

同一故事骨架可用于比较风格迁移：角色有明确目标，遇到障碍，首次尝试失败，作出有代价的选择，结果回收此前的道具或伏笔。各风格允许调整镜头语法，不能只换一个“水彩/写实”形容词，也不能将短故事机械拉长。

另做无旁白视觉说明片：以物品操作、产品流程或空间变化为主题，靠动作、画面安排与合格音效让观众理解。不能以长字幕或人物逐句解说替代核心视觉因果。若测试人物对白，沿用 D 的独立验收。

## 实际生产要求

使用六员正式路径完成计划、剧本、资源、场景、镜头与装配。检查每个节点真实输入输出及任务回执，保留合法素材复用。外部脚本可准备夹具与做媒体检查，不能代替 Agent 决策后声称自主生产成功。

Group 是故事段，镜头数量由叙事与动作决定，不设机械固定数量。Agent 根据当前端点、身份信息、机位变化和剧情决定直接接续、重新建立或修复。不能让执行提示词把每镜方法全部指定好后，仍声称已验证 Skill 自主选择。

全部作品禁止旁白；保留合格环境声和动作声。音乐是否使用由作品计划决定，不预设当前模型已完全取消音乐。

## Skill 收口

1. 核对正式权威文件及各 Agent 可绑定范围，将 A—D 的可复用规则归位；装配不能绑定时继续使用正式角色政策，不伪造新增 Skill。
2. 规则至少覆盖：实际模式能力检查、组内身份再锚定、组首自主选择、起止状态、正常切镜与桥接、小偏离修补、大偏离根帧修复、正式选择及下游 stale、无旁白和音效保留。
3. 区分模型无关制作原则与 Provider 参数，当前不可执行路径保持明确禁用或降级；一次成功不能写成所有模型的保证。
4. 给规则附对应证据与反例。实验项目细节放报告，不将所有案例堆入核心 Skill。
5. 冻结正式版本、配置和输入契约。若复验中改规则，产生新版本并重新完成受影响复验，不沿用旧版通过声明。

## 新窗口盲测与复验

开全新 Agent 会话，用冻结正式 Skill 输入新故事，只给作品目标、约束、批准资产与用户允许的审核点，不透露每镜“标准答案”。验证它自行读取项目事实、选用正确路径、识别错误端点、保留合格片段并完成正式交接。

完成冻结后的三轮独立生产复验。三轮应使用独立 run/会话和不完全相同的故事挑战；不能把同一条视频播放三遍算三轮。分别覆盖连续动作与身份、多人物道具与对白、风格迁移与视觉因果。每轮都查实际出站思考模式与所用 Skill 指纹。

穿插刷新、后端中断或晚到回执演练，确认诚实恢复和版本归属。具备自动续跑就验证自动续跑；不具备则验证保留轨迹与明确中断，不能改写为已自动恢复。

## 内容验收与封板标准

整片观看后回答：无旁白是否仍能理解目标与转折？失败是否改变后续选择？角色、道具、空间是否持续正确？动作起止是否完成？声音是否有意外旁白、乱语或串线？剪辑是否可理解？风格是否稳定？

技术通过、内容人审和正式 select 分别记录。只有冻结版本在独立会话中重复通过所声明能力、重要失败有明确处理边界、用户审核完成，才可将相应范围标为正式验收。无需宣称系统适合所有模型或不存在任何缺陷。

## 最终交付

交付 `PHASE48_E_REPORT.md` 和 `PHASE48_FINAL_REPORT.md`，包含全批状态、最终 diff、正式 Skill/角色政策版本、能力适用范围、独立 run 证据、可播放作品、失败片段、用户选片记录、未解决问题与恢复说明。所有计数从证据索引计算，并列出分母和排除项。

明确指出后续工作属于模型专项优化、内容迭代还是基础缺陷；在六员和现有 Skill 收口前，不提前扩建复杂工作流功能。

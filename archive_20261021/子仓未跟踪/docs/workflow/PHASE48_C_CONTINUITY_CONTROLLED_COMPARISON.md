# Phase48 C：接续方式的受控对照

先读 [总控计划](PHASE48_00_REVIEW_RESEARCH_AND_BATCH_PLAN.md) 和 A 批能力表。目标是判断不同接续路径各适合什么镜头，不能预设直接尾帧最差或重建首帧最好。

## 方法定义

| 路径 | 输入与语义 | 需要防止的误称 |
|---|---|---|
| 独立首帧 | 依据批准资源和下一镜计划建立首帧，再生成视频 | 不称为直接继承前镜尾帧 |
| 直接尾帧 | 前镜真实末帧作下一镜首帧输入 | 仍检查实际输出，不能预先保证逐像素继承 |
| 重建首帧 | 前镜真实末帧加批准 Look/场景依据，生成新首帧后再生成视频 | 新图是重新构建，不是原末帧 |
| 重建首帧加结束帧 | 使用上一行完全相同的新首帧，追加预先批准的结束帧 | 结束帧输入不是输出必达证明 |

原生首帧加独立 Look、多参考视频等若当前支持，可列为补充实验，不混入上述路径冒充同一种条件。模型不支持的组合记录“不可执行”，不能换模式后仍沿用原标签。

## 固定夹具

同一条件下所有候选共用同一源视频、真实末帧、角色/服装/道具/场景版本、下一镜剧情、时长、比例、模型及适配器版本。记录哪些参数因接口限制无法完全匹配。

特别要求：重建首帧与重建首帧加结束帧共用同一张首帧文件及哈希。结束帧先定义目标状态并审图，不能看完某次生成后反向挑一张有利末帧充当对照目标。身份信息已经错误的源尾帧不能偷偷换成更好帧。

## 实验条件

| 条件 | 问题 | 可接受结果 |
|---|---|---|
| 同一动作继续，尾帧清晰 | 直接接续是否减少姿态与空间跳变 | 动作和身份均正确 |
| 远景转近景，身份信息不足 | 再注入 Look 是否改善身份 | 身份恢复且切镜合理 |
| 景别或机位变化 | 是否需要重新构图 | 可理解的电影切镜，无需帧帧相似 |
| 上游尾帧身份已错误 | Agent 会不会把错误端点当可信锚 | 先修端点或明确重新建立 |

形成四种方法与四类条件的实验矩阵。错误尾帧一行先做决策检查；被规则拒绝的组合记为正确拒绝，不强迫生成。其余可执行格做真实视频对照。每格保留首次结果与后续修复，失败样本不得从统计中删除；结论摇摆时增加复验并说明所验证的假设。

## 执行与评审

1. 冻结实验清单及夹具，说明路径、预期起止状态、实际 Provider 输入。
2. 审查输入图，建立候选但不覆盖正式选片；固定比较条件，调用前记录模型能力检查。
3. 对真实视频检查开头、四分之一、中点、四分之三和结尾，另看动作峰值和接缝。抽帧不能替代完整观看。
4. 评审身份、服装、道具、姿态、空间方向、动作目标、结尾状态、剪辑理解和原生音效。所有视频禁止旁白。
5. 技术记录保留方法标签，主观评审尽量匿名候选；输出推荐及失败条件，不只挑最好的一条。
6. 把已证实的适用条件写入候选规则，交 E 收口。若修改正式规则才能继续测试，单独记录版本并复核比较是否受影响。

## 修复边界

上游端点本身不合格时先修端点。两端合格但接缝有问题时，比较保留切镜、调整剪辑、重新建立首镜、叙事过渡和桥接。正常切镜不是默认缺陷；错误桥接不能被当作连续性成功。

替换候选只有正式选用后才改变生产依赖；只复核实际依赖被替换尾帧、Look 或场景状态的下游。既要避免机械全片重做，也不能保留实质失效的下游结果。

## 交付

交付 `PHASE48_C_REPORT.md`、能力与实验矩阵、输入哈希、请求与 receipts、所有首次及修复候选、接缝比较片、人工评审结果、方法适用条件与失败边界。没有执行的格写清原因。任务成功率与内容通过率分别统计，并展示实际分母。

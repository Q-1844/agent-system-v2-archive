# Phase48 D：多人物、道具交接与人物对白

先读 [总控计划](PHASE48_00_REVIEW_RESEARCH_AND_BATCH_PLAN.md)、A 的入口/能力表和 B 的音频交接。本批所有测试禁止旁白，允许画面内人物说话。目标是验证生产规则能否处理身份关系、动作因果和可懂的对白，而非只生成两个外观不同的人。

## 项目准备

新建独立测试项目，冻结每名角色的 identity、Look、服装、批准参考、道具与地点。定义一个有明确目标、障碍、选择和结果的小故事；对白服务动作，不用解说补足画面无法表达的因果。

先确认当前模型能否输入所需参考及其组合。若不能原生多参考，允许沿正式已支持路径先做合格首帧，再图生视频；记录实际方法，不假装原生多参考成功。

## 逐级真实测试

| 级别 | 任务 | 核心观察 |
|---|---|---|
| 同框身份 | 两名角色外形明确不同，在同一地点完成简单动作 | 串脸、服装互换、人物消失或复制 |
| 空间与遮挡 | 两人交错站位、转身或前后遮挡 | 位置交换、肢体混合、错误视线 |
| 道具交接 | A 持有特定道具并交给 B，下一镜 B 使用 | 谁持有、手/爪接触、道具数量及状态 |
| 单人短对白 | 镜头内一人说明确短句，另一人不说话 | 台词、说话人、口型、背景乱语 |
| 双人轮流对白 | 两人各有独立短句与回应动作 | 说话人串位、重叠、漏句 |
| 跨镜同一角色 | 相同角色在不同镜头继续对话 | 声线身份、语气与口型连续性 |

逐级开展；低级条件失败时先诊断，不盲目堆复杂动作。之后将合格能力放进同一完整小故事，核对整链交接。

## 道具与空间账本

每镜明确开头与结尾的角色位置、视线、持有者、道具状态和动作目标；字段以现有 canonical 能力为准，尚无结构字段的内容用可追溯计划记录，不能假造数据库实体。

抽查真实视频时核对：交接前由谁持有，交接时双方是否接触，交接后是否仍出现重复道具，下一镜是否使用正确版本。镜头末尾发生了计划外动作，应按真实末态判断后续是否可用，不只根据提示词继续。

## 对白与声线验收

先冻结人物台词与说话顺序，记录模型收到的是文本提示、音频参考还是外部语音。音频参考只证明提供了参考，不能直接证明精确台词或声纹锁定。

逐句试听，ASR 只能辅助核对；检查漏词、添加乱语、角色串位、口型偏差、可懂度和背景音。相同角色的声线要跨镜对照，不以“像男声/女声”代替身份一致。

原生对白失败时归类为文字理解、音频生成、说话人绑定、口型或跨镜声线问题。已有外部 TTS/口型能力可以作为明确标注的补充路径，限于人物对白并使用现有授权声线；原生失败仍须保留。未接通的能力不能写成已完成，也不为本批默认新增复杂配音系统。

## 修复与正式选择

小偏离优先保留合格片段并做可执行局部修补。根帧身份、持有者或剧情状态错时，重建可靠输入后只重做受影响链。不能用整体静音通过对白测试，不能用旁白掩盖故事缺口。

候选与已选版本分开；提供并排可播放片段及具体评审问题，等待用户完成项目要求的正式选片。其余不依赖该选择的证据整理与独立实验继续。

## 交付

交付 `PHASE48_D_REPORT.md`、人物和道具依据、逐镜起止状态、对白表、模型实际输入、请求/receipts、合格与失败视频、原生与补充方案标签、修复成本及受影响依赖。逐项结论写“通过 / 待人审 / 失败 / 不可执行”，不能以成片存在代替身份与对白通过。

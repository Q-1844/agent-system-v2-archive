## 2. 本次审查又修了什么

| 审查发现 | R1.1 改动 | 验证依据 |
|---|---|---|
| 视觉审核已经算出 pass，最终读项目失败可能保留 pass | 最终校验异常一律转 incomplete | 最终读盘故障注入 |
| 缓存命中、或一个镜头先审完后，其他审核仍在等待；期间输入可能变化 | 整批结束时用同一最新项目快照重新校验所有可用回执，包括缓存 | 缓存命中后编辑、跨镜头晚到编辑 |
| 旧请求编译后读了新项目，再把新签名写进任务，可能使旧请求冒充新输入 | 异步准备后统一取编译快照；签名来自该快照；提交 claim 事务内再验输入与选版 | 提交前编辑时，create_video 调用数为 0 |
| 提交或下载期间用户切换选版，迟到结果可能覆盖选择 | 保存提交时的 final_video；回执写入与最终挂接分别检查；变化时保留 ID/产物，拒绝覆盖 | 提交中、下载中切换选版 |
| 迟到的明确拒绝/轮询失败可能把用户新选版标成 failed | 失败状态只更新仍对应本次提交/轮询的对象 | 两类迟到失败竞态 |
| 恢复时可能把旧 Provider 结果归到较新的无 ID 任务，或丢失原基线 | 精确按 Provider ID 找原任务；可恢复失败保留原任务、来源与基线；拒绝挂接/取消的任务不自动恢复 | 精确 ID、failed/cancelled/detached 三分支 |
| 无队列兼容恢复失败后可能把用户新选版重新标 queued | 兼容路径挂接和失败标记都检查原任务/选版 | 兼容恢复下载中换版 |

已知 ID 的回执如果因用户换版未写回正式视频记录，会在任务中保留 `unattached_provider_receipt`。它需要后续按 ID 核对；本批没有后台过渡池消费者自动接管它。已拒绝挂接的本地产物类似保留在 `unattached_artifact`。两者都是保护性留存记录，不能称为完整过渡池。

## 5. 不耗配额的效率模拟

使用真实 `LiveReviewSession` / `run_independent_review`，模拟 6 个镜头依次生成。每镜生成固定延迟 0.12 秒，每帧视觉固定延迟 0.06 秒，每镜 3 帧，三个模式各运行 3 次。只有视觉和帧提取被替换为假实现；没有真实网络或 Provider 请求。

| 模式 | 总耗时中位数（秒） | 生成结束后的审核尾部（秒） |
|---|---:|---:|
| 生成后串行审核 | 1.877 | 1.132 |
| 生成后双路审核 | 1.309 | 0.559 |
| 生成与双路审核重叠 | 1.010 | 0.257 |


实验验证软件中审核可以与生成重叠，且最后复用对应版本回执。所有组均完成 18 次假视觉调用，没有通过漏审取得更短耗时。该实验不包含真实模型时延、请求限流、配额、画面质量和复杂返工，不能外推生产提速百分比。复现实验脚本与每次采样 JSON 一并交付。

## 6. 下一步顺序

1. **本机隔离回装验收。** 先运行 43 个安全用例、前端完整构建和恢复回归；核对原有失败，保留未解释的差异。
2. **实现过渡池与接纳协调器。** 候选记录任务来源、输入基线、视频版本、审核回执、预算与状态；正式接纳时统一检查基线、权限代际和选版。

4. **持久化依赖派发和容量控制。** 能做的节点立刻推进；依赖未满足的节点不占工作槽；重启可恢复，重复事件不重复派发。

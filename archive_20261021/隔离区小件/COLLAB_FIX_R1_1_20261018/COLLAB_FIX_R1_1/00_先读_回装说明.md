# 协作系统首批修复包 R1.1（审查修订版）

本包以你交接的 `COLLAB_CODE_HANDOFF_20261018_1745.zip` 为基线，包含 22 个变更文件（16 个运行代码文件、6 个测试文件）、差异文件、安装与回滚工具，以及测试证据。原包中的 FirstFrame REST 未提交修改已保留。本包是源码补丁，不是整个项目的替代安装包。

请先看 `03_最终审查与完成范围.md`（本次审查结论），再看 `01_修复报告与后续方案.md`（首轮修复背景），再把 `02_交给ClaudeCode的回装执行文档.md` 交给本机 Claude Code。

## 选择安装入口

- **尚未安装 R1：** 使用根目录 `apply_patch.py`，从原交接包一次应用全部 22 个文件。
- **已经完整安装 R1：** 在 `upgrade_from_R1` 目录使用其中的 `apply_patch.py`，只升级本次审查修改的 4 个文件。命令参数相同。
- **本机还有其他修改或处于混合状态：** 默认预检查会拒绝清单内不匹配的目标文件；先人工合并，不强制覆盖。

在对应完整基线下，两种入口得到相同的 22 个交付文件；每个入口仅校验自身清单中的目标文件。升级回滚只退回 R1；要继续退回原交接代码，再使用 R1 当时的源码备份回滚。已验证完整应用、升级、分层回滚和哈希一致性。

## 回装方法

1. 等待正在执行的生成任务结束，记录无法确认提交结果的任务，然后停止后端。另行保留本机项目与运行状态备份。
2. 将本补丁解压到项目目录外。使用项目原来的 Python 环境（安装器需要 Python 3.11+）。
3. 在补丁目录中运行预检查。下面路径应替换为本机真正包含 `api_server.py`、`src` 的源码目录：

```powershell
python apply_patch.py --project-root "D:\实际路径\animation-storyboard"
```

只有结果为 `dry_run_ok` 才继续：

```powershell
python apply_patch.py --project-root "D:\实际路径\animation-storyboard" --apply
```

4. 保存命令返回的 `backup` 路径。安装器在项目内 `.collab_patch_backups` 保存被替换源码的原始字节；不迁移项目状态，不安装依赖，不处理旧任务。
5. 在独立测试副本中验证后，再重启本机后端。首轮使用 Fake Provider，确认无误后再进行少量真实任务测试。

**如果提示 base mismatch，不要直接复制覆盖。** 这说明本机文件与交接包不同，应逐文件合并并复核。安装器会先核对全部目标文件和补丁内容哈希；已经完整应用时返回 `already_applied`。

## 回滚方法

停止后端，将下面路径替换为安装时实际返回的备份目录：

```powershell
python apply_patch.py --project-root "D:\实际路径\animation-storyboard" --rollback "D:\实际路径\animation-storyboard\.collab_patch_backups\实际备份目录"
```

若应用后又编辑过目标文件，回滚会拒绝覆盖这些编辑，需要先人工处理冲突。源码回滚不会撤销应用后产生的项目数据或视频。

## 包内内容

- `changed_files/`：全部修改后的源码与测试文件，按原项目相对路径排列。
- `changes.patch`：供审查的统一差异；回装以安装器与文件哈希为准。
- `PATCH_MANIFEST.json`：每个文件的前后 SHA256，以及交接包摘要。
- `validation/`：原始和修复后的有效全量测试记录、差异清单、定向测试记录、安装器验证及前端编译结果。
- `validation/run_offline.py`：测试入口，仅可对独立测试副本运行。它在 pytest 主进程阻止外部 DNS/TCP，不能替代操作系统级网络隔离，测试子进程需另外隔离。

R1.1 最终审查结果和新测试记录见 03 文档；01 中的 R1 数字为历史记录。

本批未调用真实生成服务，未做画面质量评估，也未证明生产吞吐量提升。全量测试仍有失败，详见报告，不应把本包直接当作生产验收通过的版本。

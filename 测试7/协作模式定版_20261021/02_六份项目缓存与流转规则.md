# 02 六份项目缓存与流转规则（候选 C1 详细规格——用户已深度迭代的领先候选）

> 本文件是候选方案 C1 的完整规格。**是否采用以 03 的选型结论为准**；若采用其它候选，本文件留作对照。

## 模型一句话

**A 仓 workspace/ 是一个容量为 6 的项目缓存；超出即标记淘汰；淘汰数据由 producer 在系统空闲时后台刷入 B 深库；刷写核验成功才真正释放空间。**

## 流转全规则

### 1. 创建与容量
- 用户新建项目 → 写入 `A/workspace/<项目名>/`
- workspace 内项目数 **> 6** 时，最老的一份（按最近活跃时间）被**标记**（在 `.workspace_state.json` 记 `marked_for_eviction` + 时间戳）

### 2. 标记后的行为（用户定版：保留可见可改）
- 标记的项目**继续显示、继续可修改**——用户的新改动让该项目重新变「脏」，分发时打包当时最新内容
- 不立即分发：等系统空闲/下次会话启动时的后台步骤统一处理

### 3. 后台分发（producer / 系统 agent 自动执行）
- 触发：①每次新会话启动时，workflow/会话前置步骤检查标记队列（**主机制**）②定时任务兜底（防长期无人开会话；滞留无害，数据都在）
- 动作：标记项目 → 打包整包（素材 input+成片 output+交互与流程记录，**不拆散**）→ 计算逐文件 SHA256 → 提交 **B 仓**（提交分类 `assets(<项目名>)` + `manifest`）→ 推送并核验
- **核验成功后**才从 workspace/ 释放该项目（删除本地副本+更新状态文件）；核验失败 → 保留原状、记入待办重试

### 4. 取回已淘汰项目（用户想改第 10 份时）
- 从 B 仓取回该包 → 解包回 `A/workspace/` → **重新占据一个最新坑**
- 若 workspace 已满 → 触发一轮新的标记淘汰（可能淘汰刚被取回之外的其它项目）
- **3 天时限**：取回的项目若 3 天内未改完/未提交，到期**重新标记**进入淘汰流程（活跃改动会自然重置计时）

### 5. 并发锁
- 同一项目同时只允许一个活跃会话（沿用系统既有 master_lease 写锁纪律）；两台电脑同时开同一项目 → 后到者被拒并提示

### 6. 工具（tools/）不随项目走
- `A/tools/` 是全局一份的跨项目工具集（探针/评审服务器/统计脚本）
- 全局工具按「**累计 50 份或战役收尾**」整批迁移 C 仓 archive/tools_batch_N/（先到为准）；迁移时记 SHA256
- 仅**项目专属**的临时脚本才随项目包进 B
- **永不迁移项**：`.github/workflows/`、`requirements-ci.txt`（CI 活文件，平台要求必须在本仓）

## 速度保证（用户最关心）

会话级同步：会话开始一次性把项目数据链放到运行器本地磁盘 → **对话全程本地磁盘读写，与「项目只存 A」速度完全一致** → 会话结束成果推回。B 只在会话首尾出现；**步级读 B 的姿势永不采用**。

## 成片可见性

| 需求 | 通道 |
|---|---|
| 本地看片（最快） | `D:\本地预览\`（最新战役解包） |
| 在线看片（不占本地） | Pages 观看层（D 图床模式，CDN 秒开；需要时搭） |
| 找回/审计 | B 仓归档 |

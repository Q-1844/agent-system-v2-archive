# 04 系统需实现的能力（无论选哪个候选都需要的底座）

## 1. 归档器 `tools/archive_campaign.py`
- **功能**：一键完成「指定项目打包（整包：素材+成片+记录，不拆散）→ 逐文件 SHA256 → 提交目标仓（B 深库/按选型）→ 推送重试（30 次×60s，网络黑窗实测额度）→ 核验（远端 SHA 对账）→ 输出清单」
- **形态**：系统 agent 可执行的命令行工具（**不是**只有执行侧 Claude 能跑的内部流程）——这是 producer 自主归档能力的载体
- **已验证流程**：同流程手动执行已 4 次成功（B 仓 1.87GB 实战）

## 2. 标记与状态管理（仅 C1/L4 需要完整实现）
- `workspace/.workspace_state.json`：记录每份项目的最近活跃时间、标记状态、分发状态
- 标记逻辑：容量超限→标记最老活跃；活跃改动→重置标记
- 释放逻辑：**分发核验成功后**才删除 workspace 副本（核验前绝不删）

## 3. 分发触发机制
- **主**：每次会话启动的前置步骤检查标记队列（事件驱动、幂等）
- **兜底**：定时 workflow（GitHub Actions schedule）处理滞留标记

## 4. 并发锁
- 同项目同时仅允许一个活跃会话——沿用系统既有 master_lease 写锁纪律

## 5. 观看层（按需）
- Pages 评审页：最新战役评审 HTML+mp4 发 D 图床模式（在线看不占本地）
- 本地预览：`D:\本地预览\` 保留最新战役解包（已运行）

## 6. Secrets 清单（真实云端生成启用时配置）
- `AGNES_API_KEY`（文本/图/视频生成）
- 推送令牌（fine-grained PAT：Contents RW，All repositories 口径已实测可建仓）
- 注意：secret 值永不写入仓/日志

## 7. 文档化义务（云端自足的根基）
- 全部流转纪律写入 A 仓 STATE.md 与各仓 README——**任何机器上任何 agent 照文档即可完整运行**
- 本文件夹（协作模式定版）推送至 C 仓存档，作为规格的权威版本

## 8. CI 基线（已运行，作为回归标尺）
- `mock-regression`：2847 项全量，两次运行 385 未通过逐项一致=确定性基线（157F+228E；大头=云端 fixture 缺口+已知老账）——修复只许降不许升，按 nodeid 身份比对
- `pipeline-smoke`：动画全链 28 项，**GREEN 52 秒**（GitHub 自带系统跑通动画工作流的实证）
- 工件保留 3 天（产出即迁 B，工件仅短时中转）

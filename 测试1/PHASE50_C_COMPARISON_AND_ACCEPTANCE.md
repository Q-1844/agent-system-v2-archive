# Phase 50 C｜Agnes、豆包规划与 Grok 的比较和收口

## 1. 比较问题先分清

用户计划让 Grok 根据豆包分镜，并结合 Grok 实际情况与自带 Skill 生成。支持这条路径，但它同时改变规划、模型与制作策略，属于整体方案比较，不能只归因于模型或某份 Skill。

先看共同任务下的可用作品，再用少量同镜对照解释差异；不用为了“公平”强迫每个模型采用 Agnes 的模式。

## 2. 三种比较，按有用程度推进

| 组别 | 固定什么 | 可以不同 | 能回答什么 |
| --- | --- | --- | --- |
| 共同分镜对照，优先 | 故事、人物、关键资产、动作因果、镜头语义、源时长、画幅、剪辑目标 | 合法字段、对象标签与对应模型输入路径 | 同一任务下模型与其适配方法的表现；仍不是裸模型严格对照 |
| 原生方案对照 | 共同故事意图、双人物、追船、写实风格、成片目标、评价标准 | 豆包/Grok 重新规划、镜头数、镜长、原生组合/延长/修复能力 | 整体制作方案能达到什么效果与效率 |
| 定点 Skill 对照，失败触发 | 同模型、同镜头、同输入、同源时长与其余设置 | 一个明确 Skill 决策 | 这个决策是否改善具体失败 |

共同分镜对照中，默认源时长均为 10 秒；必须使用双方实际支持的共同区间。平台不支持时记录差异，移入原生方案比较，不强行假装控制变量。成片片段的保留区间允许分别选择，但关键事件都须完整。

用户只做原生方案对照也能用于选择更好生产路线，不必补完所有组。报告明确其解释范围即可。

## 3. 比较包

B 完成故事规划后导出一份 `COMMON_INTENT`，包括片名或中性项目名、故事、两人身份与职能、船/怪物定义、关键动作与结果、写实风格、音频与成片目标。没有逐镜技术答案。

共同分镜对照另导出 `LOCKED_STORYBOARD`：每镜功能、起止状态、必须保留事件、预计可见人物、机位关系、源与保留时长、合法素材路径及哈希。使用这份包时，豆包只做表达与模型适配，不改变故事和镜头语义。

原生方案对照给豆包 `COMMON_INTENT` 和已批准的角色/船/怪物定义；豆包独立提出适合 Grok 的分镜。保存豆包原案、Grok 适配后的方案与差异说明。原生方案不读取 Agnes 的逐镜修复答案，避免结果导向地模仿失败后的解法。

同一张参考无法被平台接受时，说明变换、压缩或替代过程。无法传同样参考的条件，不报告为严格同素材测试。

## 4. 能力先核对，随后专注内容

Agnes 按 A 核验的契约执行。Grok 记录实际入口：官方 API、网页产品或第三方，以及实际模型 ID、模式、时长、分辨率和开放功能。

当前 Grok 1.5 官方文档支持首帧与独立参考组合、尾帧与内部关键帧。现行官方参考图上限已与早期材料不同，执行时重新查文档与平台，不把旧“七张”固定成 1.5 的全局规则。[S5]

共同任务下允许使用模型原生合法方法；比较修复、延长或视频编辑时明确使用的实际端点与模型。网页按钮名称不是 API 能力证明，第三方平台缺功能也不能直接归因于底层模型。

不用要求 Grok 的字段、内部流程、Thinking 设置与 Agnes 一致；要一致的是创作目标和可观察评价。

## 5. 首次结果、候选选择和人工介入

每组分别保留：首次生成、失败和废弃候选、返工方式、最后选用视频、裁切区间、人工耗时与最终成片。相同 seed 不意味着跨模型相同随机条件。

先比较首次结果，再比较经过修复和选片后的最佳可用结果；候选数与重试数同时展示。不能一边只试一次、一边反复挑选后，声称成功率直接可比。

当前项目用户曾否定的广告网站演示不作为优质基准。以本次同任务真实素材和可重现过程为依据。

## 6. 评审标准

先判关键条件：只有船长与大副两名人类、身份不交换、关键行动和结果成立、船与怪物可追踪、写实风格不被明显动画化、剪辑没有隐藏关键错误。各镜按预计可见集合判人数，不规定必须始终两人入画。

再分别评估下列维度，不用一个总分掩盖硬错误：

| 维度 | 观察问题 |
| --- | --- |
| 写实质感 | 人物皮肤、服装、船体、海水、光照是否属于同一电影风格 |
| 身份与实体 | 两人、船、怪物在远近、遮挡和换机位后是否仍可识别 |
| 动作与接触 | 手、控制物、站位、动作过程和结果是否可信 |
| 空间与追赶 | 相对位置、航向、轴线、尺度与逃避选择是否可理解 |
| 叙事与节奏 | 压力、反应、应对、结果是否连贯，镜长是否冗余 |
| 运镜 | 是否服务信息与情绪，是否扰乱身份或空间 |
| 可剪性 | 有多少完整剧情可用区间，切掉瑕疵后事件是否仍成立 |
| 音效 | 是否与画面同步，有无突兀对白、配乐、切点与电平问题 |
| 自主执行 | 是否正确加载 Skill，是否需要手工提交、参数修正或选片帮助 |
| 时间 | 首次可播放、修复后可播放、人工操作、服务等待与总墙钟 |

供用户审片的版本使用随机 A/B 名称，隐藏方案名称与技术解释；保留映射表和播放顺序。不修改生成结果以隐藏模型缺陷。先静音看画面，再听带声版本；原始尺寸与实际分辨率保留，统一播放尺度不等于增强画质。

自动审查给问题与证据，用户负责最终审美和剧情接受。一个故事只能说明本任务表现，不能概括模型全局优劣。

## 7. 数值与计时口径

每项数值由 Python 根据账本计算并做反向核验。

- 提交量、唯一受理量、完成量、失败量、未知量分开；完成率分母明确。
- 可用率同时给分子与分母；首帧可用、原片可用、剪后可用分别计算。
- 可用秒数按最终保留的有效区间并集计算，不能重复累计重叠片段。
- 原片生成秒数含失败和废弃候选的实际计量，不能只算最后选用的视频。
- 首次候选与返工后候选分开计时；人工等待与服务等待分开。
- 并发用实际受理/完成区间计算在途峰值；推理并发没有可信服务字段就不报。
- 同时写任务累计耗时与整片墙钟；不可把重叠的生成时长相加成作品耗时。

少量样本报告原始结果及波动，避免制造稳定成功率或速度承诺。

## 8. 失败归因与下一步

| 观测 | 优先下一步 |
| --- | --- |
| Agent 没有真实提交、丢任务、误载 Skill | 修正式执行/绑定，不急着改叙事规则 |
| 写实参考错误或风格冲突 | 修资产与输入，固定请求做小对照 |
| 请求正确但关键动作反复失败 | 简化动作或测试另一合法方法；保留模型能力限制假设 |
| 同镜 Grok 稳定更好而 Agnes 仍差 | 优先接入更好模型，本次结果保留为 Agnes 基线 |
| 原生方案很好但共同分镜一般 | 学习规划与适配策略，不把改善全部归为模型 |
| 画质可接受但耗时主要来自返工 | 优先改善首轮输入和定点修复，而非继续加并发 |
| 耗时主要来自无依赖任务串行等待 | 在实测限流与恢复范围内调整队列 |
| 只达到多个在途、服务仍串行 | 如实报告，保留规划/审查重叠收益，不承诺生成加速 |

本阶段完成不要求所有未测场景通过。交出本故事的完整候选与可追溯证据、用户结论或具体待评项、时间瓶颈与并发边界，以及是否继续 Agnes 优化或转模型接入的判断。

跨模型材料尚未到齐时，先完成 Agnes 侧与比较包，写“跨模型结论待用户提供真实结果”；不能凭空补写 Grok 成片表现。

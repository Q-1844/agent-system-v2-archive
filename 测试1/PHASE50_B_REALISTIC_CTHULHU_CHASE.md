# Phase 50 B｜写实“克苏鲁追船”完整作品测试

## 1. 给受测系统 Agent 的创作任务

请制作一部写实电影风格短片：海上，一艘船受到克苏鲁追赶，船上只有船长和大副两名人类角色。两人的应对推动剧情，观众能够看懂威胁、行动选择与结果。请依据你实际加载的 Skill 自行完成故事、分镜、资源、镜头方法、审片与装配。

目标成片约 60 秒，允许在 50–70 秒内完成完整叙事；横屏 16:9。剧情、人物外貌、时代、海况、机位和结局由你选择。首版无旁白、无主动配音、无人物对白，保留合格原生环境声与同步音效。不要用文字解释弥补不可理解的动作。

这段任务是受测 Agent 的创作输入。以下内容是执行者的评测与交付要求，不是逐镜答案。

## 2. 测试纪律

创建新项目与新系统 Agent 会话，固定代码、模型配置、Skill 完整包和批准资产的版本。先完成一次受测运行，再对失败作定点诊断。

导演依据 Skill 自选首帧、参考、重新建帧、可用的首尾控制和正常切镜；不给它指定某镜必须使用某方法。合法模式与能力契约可以读取，已知项目的逐镜配方不作为答案提供。

Zcode 可以修工具缺陷、添加必要观测和核验产物；如果代导演编请求、手工补交或覆盖状态，记为执行介入，该轮不能报告为全程自主。

本轮优先使用已核验的现有 Skill。专业 Agent 返回的新包作为独立候选，保留原包、diff、来源与哈希；不能在一轮运行中途替换并拼成一次成功。

## 3. B0：先规划完整故事

编剧先给出片名、简短故事、人物功能、威胁、应对、结果和风格意图；导演随后形成分镜计划，不先生成视频再倒拼剧情。

剧情至少具有：威胁被发现、追赶压力上升、两人采取有联系的行动、行动带来可观察结果。允许开放结尾或失败结局，但不能靠突然消失的怪物或无原因跳场收尾。

镜头数量由导演决定，以完整叙事和可生成动作容量为准；不强制凑镜数。每镜源视频至少 8 秒，默认 10 秒，常规在 8–12 秒内安排。保留时间单独估算，不将源素材时长求和冒充成片时长。

如果预计成片不足，应补有戏剧用途的反应、空间或结果，而非复制片段、异常慢放或黑场凑时长。如果超长，优先去除冗余；不能删掉理解关键行动所必需的过程。

剧情计划进入项目事实。执行过程中重大改写另存版本、说明影响；原计划仍用于比较，不在看到失败后偷偷降低任务目标。

## 4. B1：写实资产从写实素材开始

建立以下可追踪资产，不沿用插画风 Look 作为本片默认身份参考：

| 对象 | 最低需要固定的内容 | 检查重点 |
| --- | --- | --- |
| 船长 | 身份、面部、发型/胡须、服装、显著识别点 | 写实皮肤与织物；与大副可区分；镜头变化不换人 |
| 大副 | 身份、面部、服装、显著识别点 | 不能借船长帽子或脸维持“二人”假象 |
| 船 | 船体轮廓、尺度、船首/船尾、驾驶区域、关键设施 | 外景与甲板同一艘船；船长有可操纵的合理控制物 |
| 克苏鲁 | 同一怪物的轮廓、头部触须、体表、显著形态、尺度基准 | 远近与遮挡后仍是同一实体；不能退化为泛化章鱼 |
| 海域/场景 | 时间、天气、光源、地标或可识别空间、追赶方向 | 波浪与光线一致，背景不随镜头随机改写 |
| 剧情关键道具 | 功能、状态、持有者、是否必须出现 | 只为实际剧情建立，不为覆盖表强塞交接 |

写实风格允许幻想怪物，但人物、船、材质与光照应像同一部真实拍摄加视觉特效的电影。避免塑料皮肤、游戏截图质感、随机霓虹与动画化服装。

参考资源保存完整主档及镜头可用的单视图。多视图板可以供审查，不能无差别直接作为生成输入，防止模型把不同视图解释成分身。按镜头选择必要素材，不规定参考越多越好。

人物批准参考应显示身份与服装；船的参考要足以说明整体与拍摄区域。怪物固定可识别特征，表现角度可以变化。为场景维护简明空间定义，不需要引入复杂 3D 工具。

先进行轻量写实输入核验：无人的船与海、单人物、两人同框、怪物尺度关系。优先从正片本来需要的首帧或样本中完成，不另生产一套大型探针。

如果无身份限制的画质样本很好而绑定人物后恶化，记录为输入/参考策略候选问题；该对照不能单独证明模型身份能力优劣。

批准素材遵循系统现有机制。可先向用户交出具体参考候选并同时推进不依赖其定版的工作，不额外增加每镜人工确认。

## 5. B2：分镜与状态账本

每镜至少记录下列内容；可使用现有 canonical 字段或附属实验文件，不为表格强改全库 schema：

| 字段 | 内容 |
| --- | --- |
| shot_id / revision / beat_id | 该镜头服务哪个剧情节点 |
| 功能与动作 | 一个主要动作，以及可容纳的反应和结果 |
| 源时长 / 预计保留时长 | 生成容错余量与剪辑节奏分开 |
| 预计可见角色 | 两人、其中一人或无人；遮挡与离画原因 |
| 起始/结束状态 | 人物位置、姿态、持物、船航向、威胁位置、环境状态 |
| 镜头与空间 | 机位、轴线、景别、运动动机、与相邻镜空间关系 |
| 必须保留事件 | 使行动和结果成立的关键过程，附预期可观察证据 |
| 输入依据 | 身份参考、船/场景参考、状态参考及各自版本 |
| 方法决策 | 选择哪条合法生成路径，以及简短理由 |
| 依赖 | 仅共享批准资产、依赖剧情状态、或依赖实际裁切端点 |
| 审查与裁切 | 原片问题、可保留区间、关键事件是否完整 |

追赶关系按世界空间与相对位置定义，不规定所有镜头都必须屏幕左向右。跨越轴线或改视角时，需要建立机位关系，避免观众误认为船驶向怪物。

船长与大副的姿态、制服湿损、持物和站位可因行动改变，但变化须有原因。双人物测试不要求每镜都出现两人；远景看不清脸时，不能宣称该镜人物身份已经通过。

## 6. B3：生成与并发

依据 A 的实际探针选择保守可用的在途上限。先并行独立资产和不依赖实际视频端点的镜头；连续动作组按端点依赖顺序执行。

准备充分的镜头计划后再发出请求，避免导演每完成一镜才临时猜下一镜。输入素材、顺序、对象指代、实际编译 prompt、模式、时长和模型须保存。

结构化计划用于导演判断；给模型的 prompt 按当前 Skill 编译，突出本镜头动作、运镜、结果与声音意图。静态资料由适当输入承担，不机械地把完整角色百科重复塞入每镜。

源视频生成长一些只是给剪辑余量，不能保证完整动作正确。导演应把必要动作放在可容纳的时间内，不要求模型在一个片段里连续完成多项无关大动作。

每一候选先收货再审查，保留首次结果和所有失败。不能用执行者直接 REST 补交掩盖 Agent 失败，也不能把“收费替代模型出片”计入免费主链。

## 7. B4：视频审查，检查过程而非只看首帧

审查整条原片及拟保留区间。均匀抽帧只用于初筛；人物交叉、遮挡、操作、怪物接近与剪辑端点等关键窗口加密检查，必要时直接看视频。稀疏帧未发现问题不能写成全程正确。

| 风险 | 检查 | 处理 |
| --- | --- | --- |
| 两人交换身份/分身 | 对照预计可见集合、脸、服装、遮挡轨迹 | 硬错误阻止该区间装配 |
| 船长操作悬空 | 手、控制物、身体位置、动作起止 | 关键操作错误返工；不能删掉全部操作而保留凭空结果 |
| 怪物或船乱变尺度 | 用船体、海面与固定形态评估关系 | 区分透视变化与实体变形，不靠单一像素阈值 |
| 船首/航向反转 | 看世界空间、轴线、相对追赶与建立镜头 | 合理换机位允许；无理由反转修复 |
| 道具或损伤状态跳变 | 比较相邻片段与状态账本 | 正常变化需有因果，关键跳变返工 |
| 海面/材质/光线动画化 | 与已批准目标风格对照 | 判为风格偏离，不笼统判身份错误 |
| 源片尾部有瑕疵 | 看能否在完整事件之后合法截断 | 可裁切，但下一镜必须使用实际保留端点 |
| 关键事件中途断裂 | 接触、操作、威胁导致的结果缺失 | 禁止靠隐藏关键过程宣称成功 |
| 审查器无法判断 | 保留不确定说明与具体画面 | 转人工评审，不能自动算通过 |

不应把海面倒影、合理遮挡或真实离画计为额外人物。不能把残留分身判为“背景路人”，本片只有两名人类。

## 8. B5：修复、选片与传播

先定位最早错误：批准素材、首帧、请求组装、视频过程、裁切、接缝或装配。每次说明改变什么，保留其它变量。

- 输入身份或写实风格错误：修对应素材/首帧，不靠长视频提示词掩盖。
- 正确首帧中的关键动作生成失败：先简化动作容量或更换合法策略；保留成功区间，补必要动作时保持因果。
- 非关键尾段错误：若关键事件和结果已完整，调整保留区间，重新审查其端点。
- 换机位的接缝问题：从真实状态重新构图或正常切镜；不强迫沿用上一镜构图。
- 错误上游端点：先修上游，禁止继续接力传播。
- 工具或任务恢复错误：归为执行问题，不能改剧情来让完成判定通过。

实际保留区间按 `[in, out)` 描述，接力帧为区间内最后一张真实解码帧，记录 PTS 与时间基准。不能直接取 `out` 秒处的下一帧，也不能假设源片都是恒定帧率。

未选用的新候选不自动改变正式依赖。选用视频或保留端点改变时，只让实际读取该版本或端点的下游失效；用同一身份素材独立生成的其它镜头不自动全重做。

避免无依据地反复抽签。对同一失败连续重试仍无改善，暂停该配方并记录最小诊断对照；不能因额度足就无上限循环。本轮不启用每镜二十张首帧的批量选图路线。

## 9. B6：装配与音频

装配读取明确选用的版本与裁切区间。输出“首次完整候选”和“返工后候选”，保留逐镜源片与区间依据。首次完整候选若有未解硬错误须显式标记，不能计入可接受成片。

原生风、浪、船体、脚步、操纵装置和威胁音效合格时保留。检查切点是否出现音量突变、截断或时间错位；可做必要电平与接缝处理，不引入新旁白。

未主动请求的对白、乱码语言、突兀配乐单独记录。若声效与不合格对白在同一混合音轨，不能宣称能无损分离；必要时让该段静音并明确其代价，或返工音画素材。另提供静音视觉审片版，避免声音影响视觉比较。

ffprobe 核对源与导出时长、尺寸、帧率、音轨、PTS。成片时间按真实时间线核算；叠化产生的重叠不能重复计数。无理由变速不能用来掩盖生成速度和素材不足。

## 10. 交付与结论

交付：B_REPORT、共同故事意图、冻结分镜、写实资产包、Skill 原始包及哈希、实际请求和回执、逐镜原片、裁切版本、接力端点证据、首次与修复候选、静音版、审查与返工账本、计时账本、人工待评项和未测清单。

共同故事、分镜与素材单独导出，便于用户交给 Grok；不要只交最终 MP4。

结果分为：执行链通过/未通过、Skill 正确加载/未确认、写实素材合格/未合格、原片质量、可剪性、动作与连续性、音频、用户待评。没有用户看片结论时写“技术候选完成，等待审美与剧情验收”。
